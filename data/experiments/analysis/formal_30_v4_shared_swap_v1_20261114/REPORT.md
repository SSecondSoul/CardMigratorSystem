# 共享记录交换的源浅投影修复 v1（2026-11-14，仍非整组件通过）

本轮只提升 Vue→San 源码迁移正确率，不实现 Ref/provider 互操作或增加输入要求。模型请求0，不启动服务器／浏览器，不切换人工页，不改标准 San、冻结旧证据或原始批次统计。

## 源码差异

moveItem 的 Vue 源方法先对 dayItems 做浅数组副本、交换共享记录的 start，再以 Object.assign({}, record) 浅复制选中日记录，写回 items、写 saved、通知。San 生成件却对写回记录递归 clone。两者在普通标量展示中可能一样，但嵌套引用身份、循环对象及异常行为不同。

新 source_shared_swap_semantics.cjs 按完整源码 AST 和现有目标方法识别此类结构：源两参数／边界返回／两次共享字段写／局部映射／浅投影／顺序根提交及通知必须完整匹配；目标 slice/map/clone 的词法绑定和完整函数体必须符合有界形状。未知 helper、额外效应、变化的 guard／索引／提交／事件、源 watcher、全局遮蔽／显式改写、字段冲突等拒绝改写。名称和事件名不是允许清单。

修复从源码派生整个方法，只将已证明的字面量状态访问／提交映射到 San data API；保留 native slice/forEach/map/Object.assign、共享记录先写及未选中记录身份、通知顺序、原边界和异常，不发明整数 guard 或深复制。只改变 moveItem；所有其他 script AST、template、CSS 保留。

**这不是 fresh-record/detachment 证明。** 没有修改 ValidateStage、既有 alias checker 或校验阈值，nested_state_mutation 仍报告；公开任意动态 setValue 仍未恢复。

## 检测／修复／保护协调

接入共享源码分析、repair 前处理与模拟返回后处理、repair Prompt、独立候选门。新 source_shared_record_projection_not_landed 检测与 shared_record_contracts 跟踪投影是否真实落地；伪造 validation_passed、清空诊断、移除源契约或退回深克隆仍被拒绝。

组合回归暴露过一处真实协调缺口：目标没有事件包装器时，初版检测过早依赖目标方法，包装器补齐后才显出投影缺陷。现改为先按源码报告契约；同一 AST 事务中，只有之前事件规则已给出的完整源证明才可授权配套改写，实际校验仍要求最终方法存在且函数体正确。事件＋记录更新＋交换投影可原子组合，固定点和真实 ValidateStage 候选门均验证，不靠多跑一轮碰巧暴露缺陷。

## 必须保留的边界与新反例

1. **共享原地写入仍待完整通知／提交证明。** 源方法本身也会改变旧记录，不能为消除警报盲目深复制。dayItems 仅作已声明 computed 依赖边界，本规则不证明其内部实现全面等价。
2. **任意动态实例 setter 不能直接映射为点路径。** 原生对照中 Vue setValue('draft.start','literal') 创建字面量实例键，draft.start 仍09:00；San data.set('draft.start',...) 却修改嵌套 start。Vue 对未声明 lateField 的实例赋值也不等于加入响应式 data。探针只做直接对照，没有给生产组件安装 naive setter，也不要求用户提供 provider／能力协议。
3. **初始化还存在同类深／浅克隆差异。** 向 initialItems 传入带 meta 对象的合法数组，Vue created 与 San inited 都创建新数组／新记录，但 Vue 保留 meta 引用，San 递归 clone 不保留。此处未被本轮方法修复覆盖；boundary_probes.cjs 和 boundary_observations.json 保存确证反例。它未计成新增生产诊断，也没有被169项“方法＋保护”成功隐去。不能将“当前只剩2条静态诊断”等同于“只剩2个实际问题”。

boundary_probes.cjs 的 stdin 为 {vue, code, runtime}；runtime 只用于本地测试 oracle，不保留 Vue 驱动迁移后的 San，不是互操作实现。
