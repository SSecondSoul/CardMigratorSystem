# 源浅复制记录更新闭环 v1

日期：2026-11-14。对象：TripItineraryPlanner 的 updateDraft；仍为部分组件修复，不是全量通过。

## 根因与本次处理

Vue 原方法通过 Object.assign({}, this.draft, { [field]: value }) 创建浅复制记录，再通过源 setter 更新字面量根字段 draft。目标先调用递归 clone，再改复制结果并 data.set：旧别名分析把复制结果也追踪为原状态；此外深拷贝会丢失源码保留的嵌套引用身份。不能仅删除 nested_state_mutation，也不能把“值看起来一样”当成完整等价。

本次按完整源方法恢复浅复制与一次根提交，保留计算属性键、数值转换和原表达式求值。不是直接手改生成的 San，也没有放宽旧克隆别名检查。

## 通用规则与边界

新增 source_record_update_semantics.cjs，经既有 source_phase／bounded AST 链接入 repair 前处理和模型返回后处理。只支持明确源模式：两个简单参数、单条字面量根更新、精确的源 setter 赋值体、Object.assign 新对象及单个计算属性。目标仅在五条已识别的读取／求值／复制／赋值／提交语句和精确不可变 clone 定义匹配时自动改写；不执行 clone、不信任函数名。

拒绝未知副作用、参数错配、错误提交、全局覆盖、源与目标 options 冲突、间接导出、保留生命周期方法，以及 Vue 不代理的 _／$ 开头 data 根名。不恢复通用 setValue(key,value)，也不把记录内的点号键转换为 San 路径。

校验通过共享源分析新增 source_record_update_not_landed；repair Prompt 补充浅复制、字面量根提交和未知分支保留要求；候选门独立重算契约，拒绝丢失契约或通过清空诊断伪造成功。没有修改生成 Prompt、服务器路由、通过阈值、旧 detached_record 证明器或人工页面。

只把测试改为原生实测顺序，生产修复逻辑未因该失败而调整。后续另收紧了保留根名／options冲突／直接导出边界，再重新固定版本运行最终95项。没有吞掉真实反例或把失败记作成功。
