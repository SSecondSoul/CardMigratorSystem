## 项目定位

本项目是一个 Vue 到 San 的前端卡片迁移系统，核心目标是：

```text
Vue 组件 -> SSM 结构化中间表示 -> 大模型生成 San -> 校验 -> 视觉/结构评估 -> 修复 -> 再校验
```

## 当前阶段进度摘要

当前 pipeline 已经形成第一版闭环骨架：

```text
generate -> validate -> visual_eval -> repair -> validate -> visual_eval
```

当前已完成：

- `generate.py`
  - Vue/SSM 到 San 的生成阶段。
  - 没有 SSM 时会调用 `SSMFactory` 生成 SSM。

- `validate.py`
  - San 代码级校验。
  - 包含 SFC 结构、San 基础格式、San script 可执行性、Vue 语法残留、San/SSM 一致性、dataTypes 类型、生命周期映射、事件绑定完整性、computed/watch、migration_hints 落地校验。

- `visual_eval.py`
  - Vue/San 渲染快照与 DOM tree 结构评估。
  - 当前结构相似度阈值为 `0.95`。
  - 当前还不是真实浏览器视觉评估。

- `repair.py`
  - 修复阶段第一版。
  - 消费 validate/visual_eval 报告，构造 repair prompt，调用 repair client，输出修复后的 San。

- `orchestrator.py`
  - 过渡编排层。
  - 已支持一次修复闭环，并保留初次和修复后的 validate/visual_eval 结果。

## 当前最重要的未完成事项

当前最值得继续推进的是：

1. 将一次修复闭环升级为多轮修复闭环。
2. 实现规则：结构分数或视觉分数低于阈值，且迭代次数不超过 3 轮时继续 repair。
3. 未来接入 LangGraph 条件边。
4. 后续升级 `visual_eval.py` 到真实浏览器渲染、截图和像素差异评估。

## 关键边界提醒

- `local_server` 是服务提供方。
- `migration_pipeline` 是流程消费和编排方。
- `validate.py` 负责代码正确性和 SSM 一致性。
- `visual_eval.py` 负责结构/视觉评估。
- `repair.py` 负责根据反馈生成修复后的 San。
- 循环次数、是否继续 repair、何时终止，应放在 `orchestrator.py`，未来迁移到 LangGraph 条件边。
