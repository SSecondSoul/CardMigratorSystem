## 项目定位

本项目是一个 Vue 到 San 的前端卡片迁移系统，核心目标是：

```text
Vue 组件 -> SSM 结构化中间表示 -> 大模型生成 San -> 校验 -> 视觉/结构评估 -> 修复 -> 再校验
```

当前重点已经从“搭建闭环骨架”推进到“跑真实样本、产出 repair_history、根据报告改进生成/修复质量”。

## 当前阶段进度摘要

当前 pipeline 已经形成可运行的多轮闭环：

```text
generate -> validate -> visual_eval -> repair -> validate -> visual_eval -> ... -> final report
```

当前已完成：

- `generate.py`
  - 支持输入 Vue 文件路径、Vue 源码或已有 SSM。
  - 没有 SSM 时调用 `SSMFactory` 生成 SSM。
  - 调用 `generation_client` 请求 `local_server` 的 `/api/evaluation/generate`。

- `validate.py`
  - San 代码级校验。
  - 包含 SFC 结构、San 基础格式、San script 可执行性、Vue 语法残留、San/SSM 一致性、dataTypes 类型、生命周期映射、事件绑定完整性、computed/watch、migration_hints 落地校验。

- `visual_eval.py`
  - Vue/San 渲染快照与 DOM tree 结构评估。
  - 当前结构相似度阈值为 `0.95`。
  - 当前还不是真实浏览器视觉评估，而是轻量渲染快照 + DOM tree 对比。

- `repair.py`
  - 消费 validate/visual_eval 报告，构造 repair prompt，调用 `/api/evaluation/repair`，输出修复后的 San。
  - 每轮 repair 后由 orchestrator 重新执行 validate 和 visual_eval。

- `orchestrator.py`
  - 已支持最多 3 轮 repair 闭环。
  - 会记录 `initial_validate_result`、`initial_visual_eval_result`、`repair_history`、`final_validate_result`、`final_visual_eval_result`、`final_passed`、`stop_reason`。
  - 最近已修复 generate 后 state 丢失 `vue_file_path/vue_source` 的问题，避免 visual_eval 报告里 Vue 节点数错误显示为 0。

- `run_pipeline.py`
  - 可重复运行完整 pipeline。
  - 默认导出报告到：

```text
data/experiments/repair_reports/<source>_repair_history.json
```

## 最近改动记录

### 1. 强化 repair prompt

修改文件：

- `migration_pipeline/utils/repair_prompt.py`

目的：

- 修复 Qwen repair 输出仍使用错误 San 写法的问题。
- 之前模型会输出：
  - `props: { ... }`
  - `this.props.initialSteps`
  - `<style scoped>`
  - Vue 风格 `methods: { ... }`

当前 repair prompt 已新增：

- 从 SSM 自动提取 `Expected San Contract From SSM`。
- 明确要求 props 必须迁移为 `dataTypes`。
- 明确禁止 `props:`、`methods:`、`this.props`、`this.$emit`、`<style scoped>`、`@click`、`v-if`、`v-for`、`v-model`、`:class` 等。
- 明确要求状态读写使用 `this.data.get()` / `this.data.set()`。
- 明确要求方法直接定义在 `san.defineComponent` 顶层。

### 2. 修复 orchestrator state 丢失 Vue 输入

修改文件：

- `migration_pipeline/orchestrator.py`

问题：

- `generate_result.to_state_update()` 只保留生成结果、SSM 和 San 路径。
- `orchestrator.py` 在 generate 后直接用这个 state 调 visual_eval，导致 state 里没有 `vue_file_path`。
- `visual_eval.py` 因此认为缺少 Vue 输入，报告里出现：

```text
Vue 节点数 0
```

修复：

- 新增 `_build_initial_state(...)`。
- generate 后将原始输入补回 state：
  - `vue_file_path`
  - `vue_source`
  - `source_file`
  - `generation_instruction`
  - `output_file_path`
  - `use_node_bridge`
  - `generation_metadata`

验证结果：

```text
vue_file_path: data/datasets/components/01_simple/step/vue/step.vue
visual_eval_passed: True
vue_node_count: 6
san_node_count: 6
structure_similarity: 1.0
```

### 3. 修复 Windows 子进程 UTF-8 解码问题

修改文件：

- `migration_pipeline/utils/vue_render.py`
- `migration_pipeline/utils/san_render.py`
- `migration_pipeline/utils/san_compile.py`

问题：

- Windows PowerShell / Python 默认可能用 GBK 解码 Node 子进程输出。
- Node 输出包含中文时会触发：

```text
UnicodeDecodeError: 'gbk' codec can't decode byte ...
AttributeError: 'NoneType' object has no attribute 'splitlines'
```

修复：

- `subprocess.run(...)` 显式增加：

```python
encoding="utf-8"
errors="replace"
```

- `_parse_result(...)` 中防御 `stdout/stderr` 为 `None`。

## 关键边界提醒

- `local_server` 是服务提供方。
- `migration_pipeline` 是流程消费和编排方。
- `validate.py` 负责代码正确性和 SSM 一致性。
- `visual_eval.py` 负责结构/视觉评估。
- `repair.py` 负责根据反馈生成修复后的 San。
- 循环次数、是否继续 repair、何时终止，放在 `orchestrator.py`，未来迁移到 LangGraph 条件边。
- 如果要改 SSM schema 或 extractors，先使用 `skills/schema-iteration-checklist/SKILL.md`。
