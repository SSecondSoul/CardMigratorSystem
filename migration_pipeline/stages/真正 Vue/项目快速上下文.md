## 项目定位

本项目研究 Vue 2 单文件组件向 San 单文件组件的自动迁移，当前主链路为：

```text
Vue 组件
  -> SSM 结构化中间表示
  -> local_server 调用大模型生成 San
  -> 静态校验与 San 编译检查
  -> 轻量 Vue/San DOM 渲染和结构对比
  -> 大模型 repair
  -> 再校验、再评估
  -> repair_history 实验报告
```

职责边界：

- `SSM/`：从 Vue 提取结构化语义。
- `local_server/`：接收生成/修复请求，构造 prompt，调用外部大模型。
- `migration_pipeline/`：组织 generate、validate、visual_eval、repair 多轮闭环。
- `data/datasets/`：人工生产并验证的 Vue/San 成对组件数据集。
- `data/experiments/`：pipeline 生成物和实验报告，不等同于数据集参考答案。
- `notebooks/`：记录数据生产和迁移实验的过程、缺陷与结论。

### 校验与评估

`validate.py` 当前除基础 SFC/San 语法检查外，还覆盖：

- Vue props → San `dataTypes`；
- Vue props 默认值必须落入 San `initData()`；
- 带参数事件必须保留 `move(-1)`、`move(1)`、`select(task.id)` 等参数；
- 禁止通过 `data-args/getAttribute` 绕过事件参数迁移；
- Vue `$emit` 或其包装方法必须迁移为 San `this.fire(...)`，禁止用 `this.dispatch(...)` 代替；
- 生命周期、computed/watch、状态读写和 migration hints 的落地检查；
- San script 可执行性检查。

`visual_eval.py` 当前通过轻量 Vue/San renderer 生成 DOM snapshot，再计算：

- tree edit distance；
- structure similarity；
- tag sequence similarity；
- text similarity。

当前结构相似度阈值为 0.95。

相关文件：

- `local_server/api/evaluation_routes.py`
- `migration_pipeline/utils/repair_prompt.py`

新增或明确的规则：

- 使用 `dataTypes`，禁止 `props` / `propTypes`；

### 4. 修复轻量 renderer 的假阴性

相关文件：

- `migration_pipeline/utils/vue_render.py`
- `migration_pipeline/utils/san_render.py`

Vue renderer 现支持：

- props 默认值、`data()`、computed；
- `created()`，并在生命周期改变状态后重算 computed；
- 嵌套 `v-for` 与循环局部作用域；
- 忽略只用于虚拟 DOM 身份的 `:key`。

San renderer 现支持：

- `initData()`、组件顶层方法上下文、computed；
- `inited()`、`attached()`；
- 嵌套 `s-for` 与循环局部作用域；
- 动态 class/value/disabled；
- 忽略 `key/trackby`。

人工参考版 `KanbanColumnBoard` 现可得到 Vue/San 19/19 节点，structure/tag/text similarity 均为 1.0。
