## 项目定位

本项目研究 Vue 2 单文件组件向 San 单文件组件的自动迁移，当前主链路为：

```text
Vue 组件
  -> SSM 结构化中间表示
  -> local_server 调用大模型生成 San
  -> 静态校验与 San 编译检查
  -> 轻量 Vue/San DOM 渲染和结构对比
  -> 大模型 repair
  -> 再校验、再评估
  -> repair_history 实验报告
```

职责边界：

- `SSM/`：从 Vue 提取结构化语义。
- `local_server/`：接收生成/修复请求，构造 prompt，调用外部大模型。
- `migration_pipeline/`：组织 generate、validate、visual_eval、repair 多轮闭环。
- `data/datasets/`：人工生产并验证的 Vue/San 成对组件数据集。
- `data/experiments/`：pipeline 生成物和实验报告，不等同于数据集参考答案。
- `notebooks/`：记录数据生产和迁移实验的过程、缺陷与结论。

- `migration_pipeline/run_pipeline.py` 是完整入口。

### 校验与评估

`validate.py` 当前除基础 SFC/San 语法检查外，还覆盖：

- Vue props → San `dataTypes`；
- Vue props 默认值必须落入 San `initData()`；
- 带参数事件必须保留 `move(-1)`、`move(1)`、`select(task.id)` 等参数；
- 禁止通过 `data-args/getAttribute` 绕过事件参数迁移；
- Vue `$emit` 或其包装方法必须迁移为 San `this.fire(...)`，禁止用 `this.dispatch(...)` 代替；
- 生命周期、computed/watch、状态读写和 migration hints 的落地检查；
- Vue data 初始值与 San `initData()` 的结构化等价检查；
- `disabled`、`checked`、`selected` 等派生属性禁止使用 `{= ... =}` 双向绑定；
- San script 可执行性检查。

`visual_eval.py` 当前通过轻量 Vue/San renderer 生成 DOM snapshot，再计算：

- tree edit distance；
- structure similarity；
- tag sequence similarity；
- text similarity。

当前结构相似度阈值为 0.95。

`migration_pipeline/utils/interaction_eval.py` 还支持无模型调用的确定性交互状态对比；它能比较方法调用后的 data、computed 和自定义事件，但仍不等于真实浏览器自动化。

相关文件：

- `local_server/api/evaluation_routes.py`

相关文件：

- `migration_pipeline/utils/san_render.py`

- 动态 class/value/disabled；
- 忽略 `key/trackby`。

## 当前已知问题

1. **`visual_eval.py` 不是真实浏览器自动化视觉评估。**
   - 当前没有 Playwright/Puppeteer、真实 Vue/San runtime 截图或像素差异。
   - v6 已人工验证 5 个代表样本，但其余样本的样式、浏览器布局和运行时边缘行为仍可能漏检。

2. **包装式自定义事件当前只追踪一层。**
   - 已覆盖直接 `$emit` 和 `业务方法 -> emitEvent -> $emit`。
   - 多层包装、动态事件名、事件名不在第一个参数等情况尚未做通用调用图分析；validator 的防御性扫描仍应保留。

3. **尚无独立的正式测试集结果。**
   - v2-v6 的 9 个 pilot 样本参与过 Prompt、SSM、Validator 或 evaluator 调优，只能作为开发集/校准集，不能作为无偏的最终效果估计。
   - v6 自动流水线已完成 9 个样本，但尚未从剩余数据中建立分层 holdout 测试集，也尚未进行正式成功率、成本和失败类型统计。
   - 当前交互层仍是确定性的内存执行器，不是真实浏览器自动化；不能据此宣称完整运行时等价。

4. **prop 默认值迁移仍存在生成不稳定性。**
   - v6 的 9 个样本初始生成都出现 `missing_prop_defaults`，虽然 8 个在 repair 后通过，但 `simple_step` 连续两轮无进展。
   - 暂不因单样本失败修改 Prompt；若 holdout 中重复出现同类错误，应保留正式基线后建立新版本，并同时增加回归测试。
