## 项目定位

本项目研究 Vue 2 单文件组件向 San 单文件组件的自动迁移，当前主链路为：

```text
Vue 组件
  -> SSM 结构化中间表示
  -> local_server 调用大模型生成 San
  -> 静态校验与 San 编译检查
  -> 轻量 Vue/San DOM 渲染和结构对比
  -> 大模型 repair
  -> 再校验、再评估
  -> repair_history 实验报告
```

职责边界：

- `SSM/`：从 Vue 提取结构化语义。
- `local_server/`：接收生成/修复请求，构造 prompt，调用外部大模型。
- `migration_pipeline/`：组织 generate、validate、visual_eval、repair 多轮闭环。
- `data/datasets/`：人工生产并验证的 Vue/San 成对组件数据集。
- `data/experiments/`：pipeline 生成物和实验报告，不等同于数据集参考答案。
- `notebooks/`：记录数据生产和迁移实验的过程、缺陷与结论。

## 当前阶段进度摘要

### 数据准备

- `data/datasets/dataset_manifest.json` 当前记录 100 对 Vue/San 组件。
- simple、medium、complex 三类数据已经完成多批次人工测试和问题记录。
- 数据生产阶段已基本完成，当前工作重点已转向真实 pipeline 实验、评估器校准和批量迁移统计。

### Pipeline 闭环

当前闭环已经可运行：

```text
generate -> validate -> visual_eval -> repair -> validate -> visual_eval -> final report
```

- `migration_pipeline/run_pipeline.py` 是完整入口。
- `orchestrator.py` 支持最多 3 轮 repair，并记录初始结果、每轮结果、最终结果和停止原因。
- 默认报告路径：

```text
data/experiments/repair_reports/<source>_repair_history.json
```

### 校验与评估

`validate.py` 当前除基础 SFC/San 语法检查外，还覆盖：

- Vue props → San `dataTypes`；
- Vue props 默认值必须落入 San `initData()`；
- 带参数事件必须保留 `move(-1)`、`move(1)`、`select(task.id)` 等参数；
- 禁止通过 `data-args/getAttribute` 绕过事件参数迁移；
- Vue `$emit` 或其包装方法必须迁移为 San `this.fire(...)`，禁止用 `this.dispatch(...)` 代替；
- 生命周期、computed/watch、状态读写和 migration hints 的落地检查；
- San script 可执行性检查。

`visual_eval.py` 当前通过轻量 Vue/San renderer 生成 DOM snapshot，再计算：

- tree edit distance；
- structure similarity；
- tag sequence similarity；
- text similarity。

当前结构相似度阈值为 0.95。

## 最近改动记录

### 1. 修复 Windows Node bridge UTF-8 解码

相关文件：

- `SSM/extractors/vue_parser.py`
- `migration_pipeline/utils/vue_render.py`
- `migration_pipeline/utils/san_render.py`
- `migration_pipeline/utils/san_compile.py`

Node 子进程输出包含中文时，Windows 默认 GBK 解码曾触发 `UnicodeDecodeError`，继而使 `stdout` 为 `None`。当前子进程显式使用：

```python
encoding="utf-8"
errors="replace"
```

并对空 `stdout/stderr` 做防御处理。

### 2. 保留 orchestrator 的原始 Vue 输入状态

`migration_pipeline/orchestrator.py` 已在 generate 后把 `vue_file_path`、`vue_source` 等原始输入合并回 state，避免 visual eval 因缺少 Vue 输入而错误报告“Vue 节点数 0”。旧报告中受该问题影响的视觉结论不可信。

### 3. 强化 generation/repair 契约

相关文件：

- `local_server/api/evaluation_routes.py`
- `migration_pipeline/utils/repair_prompt.py`

新增或明确的规则：

- 使用 `dataTypes`，禁止 `props` / `propTypes`；
- 方法直接定义在 `san.defineComponent` 顶层，禁止 Vue 风格 `methods: {}`；
- props 默认值必须进入 `initData()`；
- 状态使用 `this.data.get()` / `this.data.set()`；
- 保留事件调用参数；
- Vue 自定义事件使用 `this.fire(...)`，禁止 `this.dispatch(...)`；
- 禁止 `<style scoped>` 和 Vue 模板语法残留。

### 4. 修复轻量 renderer 的假阴性

相关文件：

- `migration_pipeline/utils/vue_render.py`
- `migration_pipeline/utils/san_render.py`

Vue renderer 现支持：

- props 默认值、`data()`、computed；
- `created()`，并在生命周期改变状态后重算 computed；
- 嵌套 `v-for` 与循环局部作用域；
- 忽略只用于虚拟 DOM 身份的 `:key`。

San renderer 现支持：

- `initData()`、组件顶层方法上下文、computed；
- `inited()`、`attached()`；
- 嵌套 `s-for` 与循环局部作用域；
- 动态 class/value/disabled；
- 忽略 `key/trackby`。

人工参考版 `KanbanColumnBoard` 现可得到 Vue/San 19/19 节点，structure/tag/text similarity 均为 1.0。

### 5. 增加回归测试和实验记录

- `tests/test_migration_pipeline_regressions.py`：4 项测试，覆盖参考渲染等价、默认值/事件参数缺陷识别、正确参考实现放行、`dispatch` 错误迁移拒绝。
- `notebooks/02-migration-experiments/2026-09-21_kanban_medium_pipeline_failure_and_repairs.ipynb`：记录原始失败、renderer 修复、validator/prompt 增强、两次重跑及证据边界。

### 6. 配置人工浏览器对比页

当前尚未提交的工作区改动：

- `tests/manual/vue-test-runner.html`：加载原始 `KanbanColumnBoard.vue`。
- `tests/manual/san-test-runner.html`：加载 pipeline 最终产物 `KanbanColumnBoard_repaired.san`。

## 当前已知问题

1. **尚未完成真实浏览器人工验收。**
   - 两个人工测试页已经配置到 Kanban 原始 Vue 和最终 San。
   - 当前报告只能证明静态契约、San 编译检查和轻量 DOM renderer 通过。

2. **`visual_eval.py` 不是真实视觉评估。**
   - 当前没有 Playwright/Puppeteer、真实 Vue/San runtime 截图或像素差异。
   - 样式、事件交互、浏览器布局和运行时边缘行为仍可能漏检。

3. **SSM 自定义事件提取仍有结构性缺口。**
   - Kanban 的 `emitEvent(name, payload) { this.$emit(...) }` 未进入 `event_model.custom_events`，当前仍为空。
   - validator 目前通过扫描 `script.options.methods[*].body` 中的 `$emit` 做补偿。
   - 长期应在 SSM extractor 中正确提取包装式 `$emit` 及调用链。

4. **SSM 的 `san_event_syntax` 仍会丢失参数。**
   - `event_model.dom_events[*].arguments` 已保存 `-1`、`1`、`task.id`；
   - 但 `san_event_syntax` 仍可能生成 `on-click="move"` / `on-click="select"`。
   - 当前 prompt 和 validator 直接根据 handler expression/arguments 兜底，后续应从 extractor 根治。

5. **实验覆盖面仍小。**
   - 当前 pipeline 证据主要来自 1 个 simple 和 1 个 medium 组件。
   - 尚未对 100 对数据集进行批量 pipeline 运行、成功率统计和失败类型聚类。

6. **Git 工作区状态。**
   - 当前 `main` 比 `origin/main` 领先 3 个提交。
   - `migration_pipeline/stages/真正 Vue/项目快速上下文.md` 有本次未提交的交接更新。

## Windows 本地操作提醒

正式环境使用 conda `cardmig`。在项目根目录打开 PowerShell：

```powershell
conda activate cardmig
$env:LLM_PROVIDER="qwen"
$env:LLM_MODEL="qwen-plus"
$env:LLM_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
$env:LLM_API_KEY="你的真实 API Key"
python -m local_server.app
```

`LLM_API_KEY` 必须在启动 `local_server` 的同一个 PowerShell 中设置。Windows 下不要使用：

```powershell
bash local_server/scripts/start.sh
```

另开一个已激活 `cardmig` 的 PowerShell 运行 pipeline：

```powershell
python migration_pipeline/run_pipeline.py `
  --vue-file data/datasets/components/02_medium/KanbanColumnBoard/vue/KanbanColumnBoard.vue `
  --output-file data/experiments/pipeline/KanbanColumnBoard.san `
  --max-repair-rounds 3 `
  --include-state
```

运行回归测试：

```powershell
python -m unittest tests.test_migration_pipeline_regressions -v
```

人工测试页必须通过 HTTP 服务访问，不能直接用 `file://` 打开，因为页面需要 `fetch`/`http-vue-loader` 加载组件。
