# 70 组件问题驱动的通用修复 v3

日期：2026-11-19。来源：[70 项跨版本问题分析](../../experiment_runs/analysis_70_v1_v2_20261119/REPORT.md)。这是开发回归改进，不是独立测试或已完成的新一轮真实模型通过率。

本页 v3／v4／v5 指同日开发修订及离线证据版本；生产请求支持范围仍是 `san-supported-migration-v4`，不与正式批次 v1／v2 或早期 formal_30 版本混为一谈。

## 不改变的主链与边界

继续使用 **Vue → 完整 SSM → 模型生成 San → 真实校验／浏览器评估 → 有界规则或模型修复 → 候选复测与回退**。没有恢复源 AST 整体确定性生成，没有组件名分支，没有把已有正确 San 当作生成输入。

- 保留原来的生成纯构造器与语义规则；生产边界新增一份共享 San 约束，生成、语法修复和语义修复共同使用，明确记录哈希。
- 保留修复证据去重、样式聚合和按需 SSM；不恢复完整 evaluation 机械追加。
- 阈值、模型调用额度、Token 停止线、最大修复轮数均不因本次修复上调。
- `setValue` 等方法按 AST 形状而不是名称处理。只证明用户确认的“源码内部可静态确认调用＋普通 data 状态键”，不证明任意外部公开键、Symbol、点号路径或运行时命名空间等价。
- 不覆盖历史生成文件、收据或结论。离线候选放在独立重放目录；本次离线验证没有调用真实模型、提交云端任务或迁移数据库。

| 位置 | 改动 | 不能据此宣称的事情 |
| --- | --- | --- |
| `browser/attribute-syntax.mjs`、`target-syntax.mjs` | 属性／插值级 San 错误定位；同时检查外层和真实内联 San 子组件；修复源匹配的重复 class、循环别名、模板 getter、事件修饰符和裸修饰符处理器 | 解析成功不等于行为通过；未知表达式不改写 |
| `engine/.../bounded_semantics.cjs` | 用 Babel 展开方法选项，不再要求换行缩进；覆盖父组件和子组件；名称冲突、非普通方法、歧义保留 | 不覆盖 San 生命周期／工厂，不吞掉方法冲突 |
| `engine/.../stages/repair.py` | 方法结构修复提前；连接动态赋值诊断与既有语义修复；允许有独立证明的语法规则与其他缺陷共同存在时执行 | 不因为还有视觉错误就停止所有规则；也不跳过最终质量门 |
| `engine/.../method_interface_semantics.cjs` | 检查完整调用体、参数、值、顺序和事件；识别已验证的事件包装直通内联；以完整源调用体恢复已知内部写入；区分普通 data 键与非可调用组件元信息重名 | 不按键名计数直接通过，不猜测未知键、写入 owner、捕获变量或外部函数；运行时／可调用命名空间冲突仍拒绝 |
| `engine/.../stages/validate.py`、`bounded_semantics.cjs` | 工厂读取判定从正则改成 AST，区分真正的 `this.data` 读取与默认数据中的示例字符串、注释；覆盖别名工厂和内联子组件 | 不把字符串当调用，也不把真正的前置读取、未知工厂形状当作安全 |
| `engine/.../bounded_semantics.cjs` | 检出源 computed 被漏掉／变成 San 普通方法；只搬迁完整函数体与源 getter 翻译一致、无未知捕获／副作用／方法调用者的现有实现 | 不把方法名存在当作响应式字段已落地，不凭缺失数据猜测新 getter |
| `engine/.../residual_semantics.cjs` | 内联数组 props 与源数组完全匹配时转换为 dataTypes；纯字面量 data 工厂与源一致且无现有 initData 冲突时纠正选项名，提前于依赖规则运行 | 不删除带默认值的 props 对象，不覆盖既有工厂，不转换未知函数／副作用 |
| `browser/evaluate.mjs` | 将 San parser 挂在前一节点 `.elses` 的条件分支按源顺序投影为兄弟节点；保留全部分支及后续节点 | 不压平实际 wrapper，不忽略缺失／新增／错误标签和文字分支 |
| `browser/empty-class-policy.mjs` | 区分有来源证明的数据数组索引读取与任意对象动态访问；沿用原 class 比较操作，保留全部原始 DOM | 不归一化 input value 属性，不忽略缺失节点、文本、包装、顺序或控件值 |
| `browser/evaluate.mjs`、`resource-policy.mjs` | 样式容量与原有 3,000 DOM 节点容量对齐，每个获准元素保留证据；被动内嵌图片受限解码；错误代码与浏览器栈分开 | 不静默截断样式，不放行外网、活动 SVG、脚本或超限页面 |
| `prompts/san_contract.py`、生成／修复入口 | 共享父子组件、默认值、生命周期、响应式、事件、DOM 保留要求；按诊断类别给修复清单；反馈字节不变候选 | Prompt 有规则不等于模型一定遵守，必须用真实新批次验证 |
| 规则拒绝缓存 | 只抑制该父版本下完全相同的已拒规则候选，而不是禁用全部不同规则候选 | 拒绝后的候选仍需重测，不增加自动重试／费用额度 |

## 全类别处理，而非“所有样本已修好”

所有历史诊断必须进入覆盖矩阵：语法；默认值／初始化／子组件；事件与拖拽；动态赋值／记录更新；computed 与响应式；模板及渲染 DOM；模型输出与预算；浏览器环境。已有通用规则继续复用；无法完整证明的情况由相关证据进入模型修复，仍未解决时保留失败。

尤其不能把以下情况改判通过：真实节点／数值／优先级／日期缺失、控件选择错误、错误事件参数、启动时序改变、未知动态键、原生 value 属性与 live value 的差异，以及内联组件尚未从 Vue 语法迁移完成。

曾验证 `attr-class`／`attr-value` 反射候选，但当前 San 原生元素上未取得预期 DOM 效果。正向兼容性验证失败后**未接入生产，也未放宽 value 属性比较**。这类真实或仍未证明的差异继续保留，不用额外兼容模块冒充修好。
