## 实际补齐了什么

- 保留原 `setValue(key, value) { this[key] = value; }` 函数体。自动读取源 Options／AST，在真实 San constructor 内使用已验证的业务实例代理，隔离 San 原生 `data`、`watch`、`attach` 等命名空间。
- 不把键限制为源码中出现的几个字符串；字面点号／方括号键、Symbol、命名空间同名键、原生键转换及异常均有真实生产导出对照。
- Vue 模板从 AST 转为 San 模板，保留事件修饰符、循环、条件、类名和样式。模板中的方法／成员函数调用通过受跟踪的业务接收者执行，不再遗漏方法体里隐藏的响应式依赖。
- 修正两项实际反例：循环热区未记录私有表达式依赖导致选中颜色滞后；San 的旧 IE 兼容逻辑给无 value 的 option 增加了源端没有的属性。修的是实际目标更新／DOM，不是忽略评估差异。
- 目标 DOM 仍由 San 渲染；导出单个 San SFC，除 `require('san')` 外的辅助运行时代码已内联。使用固定版本独立 `@vue/reactivity`／`@vue/shared`，如实披露依赖，不加载 Vue 组件／渲染器，不在目标中挂载原 Vue。

## 如何进入唯一主链

1. 原预检查继续识别动态实例赋值；识别不等于一律放行。
2. 默认 SSM 策略下，新增编译检查对源文件做纯解析／转换，不在 Node 执行上传源码。仅完整编译并通过规范化绑定复核后登记 `business-plan.json`；不支持的形态保留零模型调用阻断和具体原因。
3. 正常提取实际四维 SSM。生成阶段将确定性产物、源／SSM／模板／运行时绑定保存成新 revision；`origin=source_ast_rule_generation`，不是模型生成。
4. 新导出使用契约对应的静态绑定校验，**不冒充旧语义校验器已经理解新的导出格式**。旧校验器、Prompt、规则继续服务普通模型路径；新路径不能只填一个静态通过布尔值，需实际重建、比对规范产物与索引中的 manifest／SSM 指纹。
5. 继续用原评估主链检查编译运行、SSM／目标结构、原始 DOM、实际控件、样式、像素及配置动作。原门槛不变，缺交互仍未测，失败不会被换算成通过。输入／输出／运行时变更使绑定失效。
6. 确定性编译运行时自身的缺陷以 `business_rule_checks_failed` 停止，保留诊断供修规则；不把大体积内联运行时反复交给模型改写，避免破坏已验证的绑定。普通模型路径的有界修复、候选复测与回退均保留。

因此这类任务模型调用 **0 次可以是正常成功**，但必须有相应质量检查通过；不是把之前的零调用阻断改名。若预检查或质量检查失败，照实失败。确定性规则成功和模型生成成功必须分开统计。

## 当前边界

生产规则先接入无外部导入的 JavaScript Options API 单组件；不按组件名判断。源码使用未实现的选项、脚本／模板语言、私有实例依赖、复杂组件树等会明确拒绝。原模型基线／消融策略不自动改成这一规则路径，避免混淆比较。

`beforeDestroy` 等 Vue 2 生命周期选项的语义／基准、复合循环键等仍有缺口，不通过简单忽略选项或改变键语义放行。普通不含该类 setter 的复杂组件继续走原模型链；本轮不宣称所有复杂组件已通过，也不宣称完整公开实例契约完成。

对 23 个含该 setter 的现有 complex 源码做了纯编译盘点：17 个可编译，6 个仍阻断。**可编译不是迁移通过**；实际 9 步交互和整图验证完成的是 CapacityPlanningBoard，其他样本需各自评估／验收。
