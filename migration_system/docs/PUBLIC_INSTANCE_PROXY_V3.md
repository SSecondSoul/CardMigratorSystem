# 公开实例代理 v3：嵌套控件写入桥接

2026-11-17。**本轮完成一项研究边界修复，尚未实现完整任意公开键契约，未接入生产。**

沿用“允许内部公开实例代理，先验证兼容性再接入”的授权，不修改 Vue 源码、不增加用户输入、不缩小任意公开键契约。不修改已封存的 v1/v2，也不回填历史通过率。

## 本轮解决的问题

v2 的源业务方法可以修改嵌套对象，但 San 原生双向控件经 `runtime.data.set('form.title', value)` 写入时仍会拒绝。两条写入路径不同，业务方法成功不能证明控件成功。

原生 San 的 `immutableSet` 会复制路径上的对象／数组。直接用于公开业务状态会破坏与 Vue 不同的共享别名、对象身份和 ref 语义。v3 在原型内部把控件写入转发到同一份源响应式状态，再更新私有 San 镜像；没有直接改生成产物。

实现位于 `research/public_instance_v3`，以 v2 源码为研究版本基线，仍使用相同独立 `@vue/reactivity` 内核。它不是第二套生产迁移链，也不加载 Vue 组件／渲染运行时到 San 目标页。

### 已实现并验证

- 嵌套对象、数组项、动态下标、字面点号／空字符串／Symbol 路径，保留别名、原对象和 ref 身份。
- 对一次原生写入收集受到影响的根，一次性更新镜像并按根通知，避免多个读取订阅产生重复通知。
- 同步源 watcher 修改另一个根或同根其他字段时，保留这些变更和通知。
- 保留调用方通知 option 的对象身份；内部强制镜像同步标志不泄漏为调用方 option。
- 原生 `silent`／`silence`／`quiet` 只抑制 San 通知，不抑制源响应式 watcher；相同值默认不通知，显式 `force` 可通知。这是**私有控件桥接策略**，不是声称 Vue 有等价的公开 `Data.set` API。
- 将通知放到内部镜像写入保护之外，避免 San 监听器回写时绕过源状态平面。

采用根级失效通知而非伪装成原生 San 的完整嵌套 change 事件；外部逐字节依赖 change.expr/value 的监听器兼容性不在本轮通过范围，不能冒充原生 Data API 全等价。

## 验证结果

| 检查 | 最终结果 |
| --- | --- |
| v2 原有有限原生对照在 v3 实现上重放 | 94 项一致，私有 vnode 图差异仍保留 |
| 新增嵌套写入 Vue／San 对照 | 5 项一致：别名、数组／动态路径、ref、特殊键、同步 watcher 侧写 |
| 原生桥接专项控制 | 8 项成立，含通知次数、option、静默、force、缺失父对象及重入拒绝 |
| 实际浏览器 | 两张隔离 Edge 页，输入框、复选框反复开关、下拉框、字面点号键输入均一致 |
| 实际 watcher | 每页 7 条同步回调，值与旧值逐条一致；不是比较空列表 |
| v1/v2/v3 合并工程回归 | 17 项通过，21.334 秒（含旧 13 项和本轮新增 4 项） |

目标页明确记录 `Vue=false`、`VueReactivity=true`，两页无 warning/error，并验证清理。两页均先公开写入 `data=null`、`watch=42`，之后控件仍正常工作。最后公开 `dispose=null` 也不破坏加载方句柄的清理。

未重跑全部系统、30 个组件或真实模型批次。这些工程测试不能叠加为论文迁移样本数，也不是 SSIM／像素完整视觉评估或真实组件人工验收。

## 本轮失败与修正

首次普通权限浏览器启动等待超时；随后在许可的隔离无头 Edge 中验证。浏览器探针又发现源 Vue 页输入变成 `staredited`：测试的三击并没有选中全文，只删除末尾字符，双向绑定本身并未在该步失效。补充失败状态诊断后，改用明确的 Ctrl+A／Backspace／逐字输入，源／目标实际控件通过。没有为修正测试而改源组件或迁移判据。

专项 4 项曾于修正后通过（5.604 秒），最终以合并 17 项为回归记录；中间运行不累计。只有最终封存包绑定最终源码，不把中间 JSON 作为当前版本证明。

## 仍未放行的边界

1. 完整 Vue 私有 vnode／渲染实例图仍未实现，保持实际反例，不用伪造空对象放行。
2. 缺失／非对象父路径不自动创建对象；源 JavaScript 成员赋值也不能直接穿过 null。当前明确拒绝，不冒充完全相同的异常种类。
3. 源同步 watcher 内再次调用原生桥接 setter 的重入仍明确拒绝；已发生的源写入不承诺事务回滚。这里的“收集／合并”指原生通知，不是数据库式原子事务。
4. 子组件／循环作用域、完整生命周期／异常捕获、所有调度交错和插件反射仍需验证。内核依赖 development 触发钩子的限制未解除。
5. 尚未实现真实 SSM 自动编译、正式 SFC 导出及真实加载器接入。控件模板是受控合成夹具，不是生产生成成功证据。

因此继续保持 `arbitrary_public_key_contract_complete=false`、`production_admission_eligible=false` 和生产 `source_dynamic_key_contract_unsupported`。本轮没有增加生产白名单、放宽阈值或要求用户付费试跑。
