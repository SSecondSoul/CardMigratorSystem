## 2. 项目介绍：面向组件的前端技术栈自动迁移

**应用背景**：搜索卡片及页面组件需要适配统一技术栈，迁移过程中需要保留展示内容、数据逻辑与交互行为。

**研究对象**：输入 Vue 单文件组件，提取结构化语义表示，通过大模型生成 San 组件，并形成检查与修复报告。

**项目目标**：将组件解析、代码生成、运行检查与反馈修复串联起来，形成可重复执行和追溯的迁移流程。

研究主线：语义建模 → 代码生成 → 一致性检查 → 反馈修复。

讲解提示：搜索场景是课题背景，当前实现以Vue到San的组件级迁移为落点。项目不只是一次模型调用，而是包含解析、约束、检查与反馈的完整工程流程。

材料依据：选题报告；SSM/README.md；migration_pipeline/README.md

## 3. 技术选型：各层工具分别承担什么职责

**源代码分析层**：Vue compiler-sfc / compiler-dom；解析单文件组件与模板 AST；；Babel parser / traverse；解析脚本并遍历语法节点

**语义与服务层**：Python：组装 SSM、跨块关联；Flask：暴露提取与生成接口；；模型客户端：封装 HTTP 调用；当前批次使用 qwen-plus

**执行与评估层**：San：目标组件编译与运行；Python 编排器：阶段与循环控制；；DOM 比较：结构与关键属性；批量 Runner：检查点与报告

分工原则：解析器提取事实，SSM 组织上下文，模型生成代码，检查器提供反馈。

讲解提示：工具依据package.json、SSM提取链路和迁移流水线实现。这里陈述仓库使用情况，不涉及外部版本能力比较。当前编排器是Python实现；不将开题规划中的LangGraph写成已接入组件。

## 5. 技术一：基于 AST 的 Vue 组件解析

**SFC 与模板解析**：compiler-sfc 拆分代码块；compiler-dom 分析模板结构；；提取节点、指令、动态属性、插槽及组件引用。

**脚本语法解析**：Babel parser 生成脚本 AST；traverse 遍历声明与表达式；；提取 props、data、computed、methods、watch 和生命周期。

**Node / Python 协作**：Node 输出结构化 JSON；Python 提取器消费并组装；；AST 路径优先；保留源码表达式和上下文，减少信息损失。

采用语法树识别代码结构，为后续关联建模和生成约束提供输入。

讲解提示：以真实AST提取为主；Node桥不可用时存在启发式回退。报告重点讲稳定的AST主路径，不把回退等同于同等质量的解析。

材料依据：SSM/extractors/parse_sfc.cjs；vue_parser.py；script_extractor.py

## 6. 技术二：SSM 结构化语义表示

**结构层**：template：节点树与指令；script：状态、计算属性与方法；styles：样式块与绑定信息；；保留模板、逻辑、样式三个维度。

**关联层**：binding_graph：状态与模板引用；event_model：事件与处理函数；style_model：类名与样式关联；；将分散的信息组织为关系。

**约束层**：metadata：组件与框架信息；migration_hints：迁移提示；san_generation_contract：生成契约；；向模型明确目标框架约束。

SSM 作为源组件与目标生成之间的接口，也为校验与修复复用语义信息。

讲解提示：正文建议统一使用结构化语义模型这一称谓；实现Schema内部名称为San Source Model。需要区分概念名与代码名。SSM不只抽象语法，还保留部分完整表达式与方法源码以支持生成。

材料依据：SSM/schema/v3.py；SSM/extractors/relation_builder.py

## 7. SSM 如何表达一个组件的完整迁移上下文

**模板侧：使用位置**：示例：按钮 disabled 绑定；记录属性名、表达式与依赖；；点击事件关联处理函数，文本绑定关联状态或计算属性。

**脚本侧：行为来源**：保留 data 初始值及表达式；保留 computed 与方法上下文；；识别状态读取、方法参数、生命周期和事件载荷。

**生成侧：目标约束**：将状态读写映射到 San 数据接口；将自定义事件映射到 fire；；派生属性采用单向插值；双向绑定限定为可赋值路径。

关键点：不仅记录“有什么语法”，还组织“谁依赖谁、谁触发谁、如何生成”。

讲解提示：该页为方法示意，不是特定样本的实验复盘。disabled等派生表达式约束可在生成提示和静态校验器中找到。

材料依据：SSM/extractors/relation_builder.py；local_server/api/evaluation_routes.py；migration_pipeline/stages/validate.py

## 8. 技术三：模型服务与约束驱动的代码生成

**统一服务入口**：Flask 接收 Vue 路径、源码或 SSM；需要时调用提取器；；将生成逻辑封装为接口，便于单样本调试与批量调用。

**提示构造**：以 SSM 作为核心输入；加入 San 语法和迁移要求；；明确初值保留、状态读写、事件与绑定规范，要求完整组件输出。

**客户端封装**：统一 generate 客户端接口；通过 HTTP 调用外部模型；；归一化代码、模型信息和 usage，保存生成文件并返回元数据。

当前生成侧的核心输入为 SSM；Vue 源码先在本地解析为结构化信息。

讲解提示：依照local_server实现描述。当前使用现成外部模型与提示约束，本版不将LoRA微调或少样本训练作为已经完成的技术。

材料依据：local_server/app.py；api/evaluation_routes.py；client/base_client.py；client/qwen_client.py

## 9. 技术四：规则检查与目标代码编译

**规则检查**：检查属性默认值与数据声明；检查 Vue 残留写法和状态访问；检查动态属性、事件及循环绑定；；将迁移要求变成可执行约束。

**编译检查**：调用 San 相关编译检查；识别目标模板和组件语法错误；；让生成代码先满足目标框架的基础可执行条件。

**统一错误模型**：code：错误类型；location：定位信息；message：诊断说明；suggestion：修复建议；；为下一阶段修复提供结构化输入。

静态规则负责迁移约束，编译检查负责目标语法；两者共同构成第一层反馈。

讲解提示：这里不把整个校验器称为完备的AST等价验证。当前ValidateStage结合规则分析与San编译检查，需要按照实际检查范围描述。

材料依据：migration_pipeline/stages/validate.py；migration_pipeline/utils/san_compile.py

## 10. 技术五：初始渲染比较与交互辅助验证

**DOM 结构比较**：对 Vue / San 生成初始渲染结果；归一化 DOM 快照并比较；；统计结构、文本与树编辑距离；检查关键属性是否一致。

**交互状态比较**：按场景执行组件方法；比较操作后状态与事件载荷；；轻量内存上下文检查，可作为浏览器验证前的辅助环节。

**浏览器辅助核验**：使用 Vue / San 测试 Runner；观察实际渲染及交互反馈；；作为代表性场景的人工核验手段，与自动指标分别记录。

三层证据分别关注初始结构、操作后状态与浏览器实际表现。

讲解提示：visual_eval当前主要基于初始渲染DOM比较，不能直接称为完整像素视觉评估。interaction_eval明确不是浏览器自动化层。截图与像素比较工具不代表已作为全批次结论的依据。

材料依据：stages/visual_eval.py；utils/dom_compare.py；utils/interaction_eval.py；tests/manual/

## 11. 技术六：反馈驱动修复与流水线编排

**修复输入**：SSM 与当前生成代码；静态诊断与渲染差异；历史修复信息；；将可定位的错误转换为修复提示。

**阶段循环**：generate → validate → visual_eval；未通过时执行 repair 并复检；；状态对象统一维护代码版本、检查结果和修复轮数。

**执行控制**：通过即停止；达到最大修复轮数时停止；连续无进展时提前停止；；保存代码、报告与停止原因。

当前由 Python 编排器实现闭环；默认最大修复轮数为 3。

讲解提示：连续无进展识别结合代码哈希、错误与结构指标。LangGraph是开题规划中的编排方向，当前以可运行的Python编排实现为准。

材料依据：migration_pipeline/orchestrator.py；stages/repair.py；utils/repair_prompt.py
