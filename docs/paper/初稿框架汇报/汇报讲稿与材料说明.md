## 1. 封面



讲解提示：开场：汇报研究定位、技术工作与论文初稿结构。



## 2. 研究背景：迁移需要同时保留结构、状态与交互

**业务需求**：搜索卡片及页面组件需要适配统一技术栈；迁移过程中要保持内容、样式和交互的一致性。

**核心困难**：模板、脚本、样式相互关联；属性绑定、响应式更新和事件机制在 Vue 与 San 中存在差异。

**研究切入**：用结构化表示组织源组件语义，再通过可执行检查与反馈修复降低迁移偏差。

研究目标：建立可检查、可迭代、可追溯的组件迁移流程。

讲解提示：这里强调组件迁移的工程需求。搜索场景是应用背景，当前仓库的验证对象是分层Vue组件；不将组件级实验直接外推为整页搜索系统上线效果。

材料依据：开题报告；SSM/README.md

## 3. 项目定位与边界

**输入与输出**：输入：Vue 单文件组件；中间：SSM 结构化表示；输出：San 组件及迁移报告

**当前验证范围**：覆盖模板、状态、事件和样式提取；采用简单／中等／复杂组件进行分层评估。

**当前能力边界**：重点验证组件级迁移。全量交互等价、真实搜索业务集成及性能收益仍需补充证据。

以 Vue → San 的实证研究支撑“Web 技术栈自动迁移”这一论文主题。

讲解提示：说明论文题目较宽，而当前实验聚焦明确的源框架与目标框架。搜索场景适配约束应在需求章节说明，真实业务验证作为待补充工作。

材料依据：local_server/README.md；migration_pipeline/batch_configs/formal_30_v3.json

## 4. 拟回答的三个研究问题

**RQ1 · 如何表达**：如何保留模板、逻辑、样式及跨块关联，使大模型获得足够完整的迁移上下文？

**RQ2 · 如何纠错**：如何将静态规则、编译与 DOM 差异转成可操作反馈，支持多轮修复和终止？

**RQ3 · 如何验证**：如何区分自动检查、交互验证与迁移成本，并判断方法在不同复杂度下的适用边界？

研究主线：语义表示 → 反馈驱动迁移 → 分层实验验证。

讲解提示：三个问题对应论文第三、四、五章。它们是初稿组织的研究问题，不能把已有工程实现直接表述为已获证明的学术创新。



## 5. 技术路线



讲解提示：依次解释输入、SSM、模型生成、规则与DOM评估、反馈修复。当前是Python编排器，LangGraph尚属后续集成。



## 6. 核心方法一：用 SSM 组织组件迁移语义

**模板与逻辑**：DOM 树、指令、插槽；props / data / computed；methods / watch / 生命周期

**跨块关联**：binding_graph：数据绑定；event_model：事件关系；style_model：样式关联

**生成约束**：保留状态初值及方法上下文；通过迁移提示与生成契约约束 San 输出，减少信息丢失。

实现链路：Vue / Babel AST → Node 解析桥 → Python 组装 → SSM JSON。

讲解提示：SSM在选题报告中解释为Structured Semantic Model，仓库README又使用San Source Model，初稿需统一术语。建议正文统一为结构化语义模型，并交代实现命名。解析优先真实AST，回退路径另行说明限制。

材料依据：SSM/README.md；SSM/schema/v3.py；SSM/extractors/relation_builder.py

## 7. 核心方法二：把检查结果转为修复反馈

**静态与编译**：检查 San 语法、属性默认值、数据访问、动态绑定与事件映射；输出定位信息和错误码。

**渲染与 DOM**：比较初始渲染的结构、文本及关键属性；结构相似度默认阈值为 0.95。

**反馈与终止**：将差异写入修复提示；复检修复结果，记录轮数、Token 和停止原因，识别无进展循环。

当前自动通过主要反映规则、编译与初始 DOM 检查；交互和像素评估须分别报告。

讲解提示：不要把visual_eval模块名等同于完整像素视觉验证。当前核心调用为Vue/San渲染与DOM比较。像素级指标、浏览器全量交互与性能评估应作为补充实验。

材料依据：migration_pipeline/stages/validate.py；stages/visual_eval.py；orchestrator.py
