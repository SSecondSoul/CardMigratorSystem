# 论文研究进度

自开题以来，本研究围绕“基于大模型的搜索场景Web技术栈自动迁移系统”，按照开题报告确定的技术路线，开展了Vue到San组件迁移的方法研究与系统实现。目前已完成结构化语义模型、模型生成、多维校验及有界修复等核心模块，形成了可执行的迁移闭环，并进入批量实验与复杂组件问题分析阶段。主要进展如下。

（一）完成结构化语义模型的设计与自动提取。针对前端组件中模板、逻辑和样式相互关联的特点，设计了包含模板结构树、数据绑定图、事件交互表和样式特征集的结构化语义模型（SSM）。基于Vue编译器和Babel解析组件源码，提取节点层次、条件与循环指令、状态及计算属性、事件处理关系和动态样式等信息，生成统一的JSON表示，为模型生成和后续校验提供语义依据。

（二）完成实验数据整理与复杂度分级。依据模板结构、数据逻辑、交互行为、样式特征和组件通信五个维度建立组件复杂度分级标准，整理了包含100个Vue／San组件对的数据集，并按复杂度分层划分为70个实验组件、20个验证组件和10个测试组件，保存组件来源、划分清单和文件摘要。目前该划分用于内部探索性实验，后续评价仍需结合样本历史使用情况控制数据泄漏风险，不能直接视为独立盲测结果。

（三）完成SSM与提示词引导的大模型生成链路。将SSM、迁移规则、输出约束和少样本示例组合为生成提示，接入Qwen-Plus模型，打通源组件输入、语义提取、提示组装、模型调用和San代码保存的完整流程。系统记录生成版本、调用状态及Token用量，便于追溯失败原因和分析迁移成本。目前模型适配主要采用提示优化与少样本示例方式。

（四）完成语义、结构和视觉一致性校验。语义层检查状态访问、事件映射、生命周期和公开方法等受支持的源代码约束；结构层采用有序树编辑距离，分别比较SSM与目标模板投影、源组件与目标组件的实际渲染DOM，并核对控件初始状态；视觉层在统一渲染条件下，通过Puppeteer获取截图和计算样式，结合SSIM、像素差异率及样式匹配情况评估UI还原度，生成差异热图与诊断明细。当前结构和UI阈值均设为严格大于95%，像素差异率须低于5%。对于已配置的代表性交互，系统可执行动作并比较观察结果；未配置的交互明确记为未测试。

（五）完成规则与模型结合的有界自修复流程。基于LangGraph组织生成、评估、诊断、修复和候选复测等节点，对可确定的映射偏差采用规则修复，对需要模型处理的问题提供当前代码和差异上下文。每个候选版本均按相同标准复测，存在退步或未获得严格改进时保留上一版本，最多执行三轮修复。系统保存候选代码、评估结果和接受或回退记录，形成可追溯的闭环执行过程。

（六）完成独立迁移工作台与阶段性实验验证。已实现任务提交、状态展示、质量评估、代码与报告下载、修复记录查看等功能，并将任务、调用和产物信息持久化。真实运行中已观察到部分组件通过当前配置下的全部必需检查，也发现了UI还原度为100%但DOM结构相似度仅为88.89%的案例，说明视觉指标需要与结构及语义检查联合使用。目前新一轮批量实验仍在推进，复杂组件的动态依赖、方法契约及交互覆盖仍需继续完善。

下一阶段将重点完成批量实验和失败类型分析，补充代表性交互场景，开展直接生成、SSM引导及有无修复等对照与消融实验，并整理迁移成功率、视觉还原度、模型成本和人工干预情况。开题报告中的LoRA方案已具备数据构建和训练模块，但尚未开展实际训练，暂不形成微调效果结论。迁移成功率、自动化率及效率提升等预期目标，还需通过统一评价口径下的后续实验验证，同时推进论文实验章节与初稿撰写。
