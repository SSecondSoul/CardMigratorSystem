# 16. 后端技术栈

后端以Python为主，采用FastAPI提供网页接口，并由独立的Worker执行迁移任务。接口负责接收请求、检查输入和账号权限、查询进度及提供文件下载；Worker负责调用前文介绍的迁移流程，便于复用已有的生成与校验程序。主要组件及其联系见图10，技术组成见表15。

图10  后端主要组件与数据流

用户提交后，接口先将任务写入业务数据库，返回任务编号和“已接收”状态。Worker从数据库中取出排队任务，执行时持续更新阶段和结果，网页定时查询这些信息。这样，用户可以先拿到任务编号，再查看进度，不必等整次迁移结束后才收到网页响应。当前采用单机单Worker串行处理，并通过运行锁避免同一时间重复执行任务。

表15  后端技术组成及作用

|技术组成|选用技术|作用|
|---|---|---|
|接口服务|Python、FastAPI|接收请求与查询下载。|
|流程执行|Worker、LangGraph|组织各阶段与修复。|
|源码处理|Node.js、Vue编译器、Babel|解析组件与检查语法。|
|界面检查|Puppeteer、Edge或Chromium|运行页面并采集证据。|
|模型调用|通义千问qwen-plus接口|生成代码与模型修复。|
|数据管理|MySQL、SQLAlchemy、Alembic|业务存储与表结构管理。|
|过程记录|本地记录、可选LangSmith|记录耗时与调用摘要。|

LangGraph把预检查、SSM提取、生成、评估、诊断、修复、候选再检查和结果保存连接起来。检查通过、源组件存在问题或修复轮数用完时，流程进入报告阶段；修复候选只有在比较后被接受，才替换当前版本。LangGraph还会记录已经执行的阶段和中间状态，便于异常后检查与恢复；恢复时仍需核对任务和配置是否一致。

源码解析和页面检查由Node.js辅助程序完成。Vue编译器与Babel负责读取模板、脚本等内容，Puppeteer控制Edge或Chromium运行Vue和San页面，采集DOM、控件状态和截图，再交给后端进行比较。Python负责组织任务，JavaScript工具负责处理组件和浏览器，两部分通过JSON交换输入与结果。

当前模型配置使用qwen-plus，单次最大输出为32768 Token，单次网络请求的等待配置为240秒，每个任务最多调用4次，修复轮数最多3轮。这些数值是配置上限，实际次数随修复设置和检查结果变化；240秒也不等于整次迁移的耗时上限。模型采用非流式返回，后台收到完整代码后再编译和校验，输出被截断时会记录失败；遇到响应结果不明确的超时或断连时，不自动重复发送同一次调用。

当前系统使用MySQL保存任务、账号、模型调用和文件索引等业务数据。Python通过SQLAlchemy和PyMySQL读写MySQL，Alembic负责管理数据表结构及版本。流程检查点仍由LangGraph单独保存在本地langgraph.sqlite3文件中，用来记录执行到哪一步及中间状态，采用SQLite格式；这部分与MySQL业务库分开保存。源码、San代码、SSM、截图和报告保存在文件目录中，数据库登记文件路径与SHA-256标识，读取时核对文件内容。具体数据表及其联系在下一节说明。

多人模式下，后端检查登录状态、任务归属和管理员权限，并记录用户用量。模型密钥由执行任务的Worker从环境变量读取。各阶段耗时及异常保存在本地；需要集中查看时可开启LangSmith，目前配置中关闭该功能，开启后只上传阶段、耗时、标识等摘要。
