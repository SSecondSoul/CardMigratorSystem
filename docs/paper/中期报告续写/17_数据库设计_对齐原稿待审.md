# 17. 数据库设计

业务库使用MySQL，已有建库核验记录共34张表：源码与当前迁移相关5张、多用户管理8张、运行与版本管理2张，另19张保留历史实验记录。表关系见图11，各表作用见表16。

同一用户可有多份源码与任务，同一源码可多次迁移，任务再关联模型调用和文件。归属表用于检查访问权限，数量关系见图中标注。

表16列出15张当前运行表，另19张表保留历史记录。

迁移任务表关联源码，分别保存提交参数和执行状态，便于对照原始输入与处理结果，主要字段见表17。

表17  迁移任务表主要字段说明

|字段|类型|说明|
|---|---|---|
|id、input_id|VARCHAR(32)|分别为任务编号和对应源码编号。|
|idempotency_key|VARCHAR(80)|识别同一次提交，取值不可重复。|
|request、binding|JSON|保存任务请求及运行实现与配置绑定。|
|request_sha256|VARCHAR(64)|记录请求内容标识，用于核对变化。|
|status、stage|VARCHAR|分别保存任务状态和当前处理阶段。|
|state|JSON|保存当前版本、检查结果及修复决策。|
|stop_reason|VARCHAR(120)|保存任务停止的原因。|
|created_at、updated_at|DOUBLE|保存创建与最近更新时间，单位为秒。|

用户、源码和任务编号为32字符，SHA-256内容标识为64字符。任务提交标识及“任务编号＋调用轮次”分别设置唯一约束；外键保证调用和文件记录关联到有效任务。模型调用记录起止时间、状态、响应与用量，响应不明时保留异常状态；各轮检查与修复决策保存到任务状态和JSON文件，登记在文件索引表中。

源码、San代码、SSM、截图和报告放在服务器文件目录，MySQL登记路径和内容标识，下载时核对。LangGraph的执行状态另存于本地langgraph.sqlite3检查点库，不计入34张MySQL表。

账号保存密码哈希，会话保存令牌摘要；用户额度与每日实际用量分表保存，按“用户＋日期”累计任务、模型调用和已知Token用量。登录尝试、审计、心跳与结构版本也分别记录。

已有MySQL原生记录显示：JSON读写、时间值往返、唯一与外键约束、事务回滚和双连接锁互斥检查通过，核验范围为存储与约束行为。
