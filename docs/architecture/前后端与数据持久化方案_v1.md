# 前后端与数据持久化方案 v1

日期：2026-11-16。状态：P2b 已实现；P2c 工作台已构建、浏览器 T3 验收待人工确认。API／SQLite／独立 worker／LangGraph 真实运行，生成／检查仍为夹具。当前范围见[工程 README](../../migration_system/README.md)及本文第 11—14 节。对应[重构总方案 r3](迁移系统整合重构方案_v1.md)。

## 1. 交付目标与范围

最终交付一个真实可运行的本地单用户迁移系统：在网页提交 Vue 及必要依赖，后端持久化任务，独立 worker 执行 LangGraph，真实模型生成／修复，Puppeteer 评估，网页展示进度、差异、版本、报告及人工确认。

假客户端仅替代开发／测试中的模型响应，不能替代真实前后端、数据库、LangGraph 或浏览器验收，更不能作为迁移正确率。完整系统仍必须达到总方案中 LangSmith、few-shot、LoRA 等技术项的实际验收条件。

首版限定本机、单操作人、单 worker 串行运行；默认仅绑定 loopback。不建设多租户、角色权限、分布式调度、线上搜索平台或 Vue/San 互操作。完整指上述范围内真实端到端可用，不代表可直接公开部署。

## 2. 首版工程选型

这些是工程实现选择，不冒称开题报告指定的 Web 技术；开题中的迁移框架与研究路线保持不变。

| 部分 | 首版方案 | 依据与边界 |
| --- | --- | --- |
| 前端 | Vue 3＋Vite＋TypeScript，轻量任务工作台 | 新建 `migration_system/frontend/`，旧根目录 `frontend/` 不覆盖；参照 [Vue Quick Start](https://vuejs.org/guide/quick-start.html) |
| 后端 API | Flask application factory、Blueprint、应用服务层 | 复用现有 Flask 经验，不把旧路由整包复制；参照 [Application Factories](https://flask.palletsprojects.com/en/stable/patterns/appfactories/) |
| 数据访问 | SQLAlchemy＋Alembic | 定义关系、事务、唯一约束与数据库变更脚本；参照 [SQLAlchemy tutorial](https://docs.sqlalchemy.org/en/20/tutorial/index.html)、[Alembic tutorial](https://alembic.sqlalchemy.org/en/latest/tutorial.html) |
| 业务数据库 | 文件型 SQLite，本机单用户／单 worker | 真实持久化数据库，不是 JSON 或内存替代。面向当前本机交付范围；扩展多主机／高并发时另评估，参照 [SQLite 使用范围](https://www.sqlite.org/whentouse.html) |
| 长任务 | 独立 worker 进程＋数据库持久任务队列 | API 快速返回，worker 调用真实 LangGraph；不在 HTTP 请求里执行完整模型链，不依赖 Flask 请求线程“后台继续跑” |
| 图状态 | LangGraph 持久化 checkpointer，独立于业务表管理 | 初期使用兼容的本地持久化实现；具体依赖版本经测试后锁定，不自行修改其内部表 |
| 文件产物 | 本地受控文件目录＋数据库元信息／哈希 | 源码、San、截图、热图及大报告不整份塞入数据库或图状态 |
| 可观测 | LangSmith 实际追踪＋本地请求收据和 trace 引用 | 不作为业务数据库，不用平台可用性决定组件是否正确 |

独立后台处理遵循 [Flask 长任务文档](https://flask.palletsprojects.com/en/stable/patterns/celery/)中的请求与长任务分离原则；该文档的 Celery 示例不表示本方案已经采用 Celery。首版选择受限的数据库队列，若未来增加并行或跨主机，再单独评估队列设施，不立即引入 Redis／Celery／微服务。

版本在实施前验证兼容并锁定；设计稿建立时未安装依赖，后续 P2b 的隔离安装与实测结果见第 11 节，不将其推广为未经测试的版本组合可用。

## 3. 系统职责与调用链

```text
网页工作台 ──HTTP──→ Flask API／应用服务 ──事务──→ 业务数据库
                          │                        │
                          │创建任务／运行记录       │持久队列／状态／事件
                          │                        ↓
                          │                  独立 worker
                          │                        ↓
                          │                  LangGraph 图
                          │                    ├─ LLM／LoRA 推理适配
                          │                    ├─ Node／Puppeteer 评估
                          │                    ├─ 独立图 checkpoint
                          │                    └─ LangSmith 追踪
                          ↓                        ↓
                      文件索引 ←────────── 不可覆盖的版本化产物
                          │
网页轮询状态／事件／结果 ←─┘
```

- 业务数据库回答“有哪些任务、哪次运行、当前 revision、各维度结果、人工意见和花费”。
- checkpoint 回答“图运行到哪里、如何恢复”；业务进度显示不能直接拼读 checkpointer 的内部表。
- LangSmith 回答“为什么走这个分支、调用耗时及 token”；其 trace 不能代替业务事务和结果存储。
- 文件存储保存大产物；数据库只登记受控相对路径、类型、尺寸、哈希和归属，不接受浏览器提交任意本地绝对路径读取。
- 业务状态与图 checkpoint 不处于同一个跨系统原子事务，不宣称“天然一致”。用 run／attempt／revision 关联并设计恢复核对，出现分歧进入复核。

## 4. 前端工作台

| 页面 | 必须可用的功能 | 不允许的替代 |
| --- | --- | --- |
| 创建迁移 | 上传单文件或受限依赖包，查看输入清单，选择允许的模型配置、props／场景、预算，提交任务 | 只有截图／静态表单；把模型密钥放入前端 |
| 任务列表 | 分页查看、按执行状态／评估结论筛选，区分排队、运行、复核、结束 | 只列最终通过组件，隐藏异常／未执行 |
| 任务详情 | 实际阶段、修复轮次、已接受／候选 revision、事件、预算和 trace 链接 | 将模拟动画或进度 100% 当作迁移通过 |
| 差异与产物 | 源／目标代码、DOM／AST 差异、截图／热图、样式差异、诊断定位、产物下载 | 将旧 DOM 分数标为像素还原度；直接在主页面执行生成脚本 |
| 人工验收与报告 | 按场景确认、填写意见，查看初始／最终／失败候选、自动与人工结论 | 人工通过后覆盖自动失败或把手工产物写成自动结果 |

首版采用分页查询和基于事件游标的轮询，不必须建设 WebSocket。刷新／重新打开页面后从后端恢复显示，不重新发起生成；网络断开应显示查询失败，而不是把任务标成组件失败。

代码以转义文本展示，生成页面在独立受限预览环境中渲染，不用 `v-html` 将源码注入工作台。现有人工 runner 保留，工作台通过显式产物索引接入；不能为了演示修改实验输入、默认主题或业务事件。

## 5. 拟定 API

以下是完整交付的设计清单，不代表全部实现；P2b 仅实现第 11 节说明的子集。API 使用版本前缀，最终错误体应包括稳定 code、message、request_id 和必要的非敏感 details；开发子集目前仅 code／request_id。

| API | 行为 |
| --- | --- |
| `POST /api/v1/inputs` | 接收源码／依赖，校验大小和路径，返回只读输入清单、哈希与 input_id |
| `GET /api/v1/configurations` | 返回后端允许的模型／评估／预算配置及其版本，不返回密钥 |
| `POST /api/v1/tasks` | 用 input_id 和允许配置创建任务，暂不隐式调用模型 |
| `GET /api/v1/tasks`、`GET /api/v1/tasks/{id}` | 分页列表及详情，返回执行状态和评估结论两个维度 |
| `POST /api/v1/tasks/{id}/runs` | 显式创建并入队一次运行；保存固定请求、版本和预算，返回 202 与 run_id |
| `GET /api/v1/runs/{id}`、`GET /api/v1/runs/{id}/events?after=...` | 查询持久化状态／顺序事件，轮询不产生新尝试 |
| `GET /api/v1/runs/{id}/report`、`GET /api/v1/runs/{id}/artifacts` | 获取初始、尝试、终态和产物索引，未知指标返回明确缺失状态 |
| `GET /api/v1/artifacts/{id}/download` | 校验归属、路径及完整性后下载；不是任意文件读取接口 |
| `POST /api/v1/runs/{id}/cancel` | 请求安全停止，不把正在计费的外部调用假称撤销；停止后保留已有事实 |
| `POST /api/v1/runs/{id}/resume` | 只恢复同一绑定版本、明确可恢复的运行，不能直接复跑状态不明的模型请求 |
| `POST /api/v1/runs/{id}/manual-reviews` | 追加场景、revision、意见与人工耗时，不修改自动结论 |
| `GET /health/live`、`GET /health/ready` | 分开进程存活与依赖／数据库／worker 就绪；不在健康检查中付费调用模型 |

运行创建、恢复和取消采用幂等键／明确状态前置条件；同幂等键不同请求内容返回冲突。默认生成新 run，不覆盖旧 run；续修／仅评估模式单列来源与成绩。HTTP 202、执行 finished、人工通过及自动综合 pass 四者含义不同。

## 6. 业务数据模型与状态

完整交付的逻辑实体如下，不与当前数据库表逐项等同。P2b 首次迁移仅落地第 11 节所述的受限子集；其余字段、实体及后续迁移仍需实现。

| 实体 | 主要内容与关系 |
| --- | --- |
| `input_bundles`／`input_files` | 输入身份、文件清单、源／依赖角色、相对路径、字节哈希；内容落文件存储 |
| `tasks` | 用户可见任务、名称和 input_id；一个任务可以有多次不可混淆的运行 |
| `runs` | task_id、执行模式、请求／协议／实现哈希、模型和预算、执行状态、评估结论、当前接受版本、图 thread/checkpoint 关联 |
| `run_events` | run_id＋递增序号、阶段、revision、事件类型与非敏感摘要；顺序唯一便于轮询与恢复 |
| `attempts` | 生成／规则／模型／复测尝试、请求指纹、响应收据、开始结束时间、错误、实际 usage 和幂等标识 |
| `artifact_revisions`／`artifacts` | 父版本、来源、接受／拒绝事实、产物路径／哈希／类型、对应 run 和 attempt |
| `evaluations`／`diagnostics` | revision、评估器／环境版本、证据层级、各维度状态、指标／阈值、原错误码／归属、完整证据引用 |
| `repair_decisions`／`candidate_decisions` | 处理的诊断、规则前提／模型请求、比较评估、接受或回退理由 |
| `manual_reviews` | 人工意见、场景、明确 revision、记录时间、实际修改行数／耗时；不回填缺失历史计时 |
| `trace_links`／`frozen_config_refs` | LangSmith run／trace 引用，冻结的 Prompt、模型、SSM、评估策略与数据清单引用 |

执行状态建议为 queued／running／review_required／finished／cancelled／execution_error；评估结论使用统一契约 pass／fail／blocked／not_run／unsupported／execution_error／unknown。finished 可以对应 fail 或 blocked，不能用数据库任务状态覆盖评估结论。

数据库通过约束保证 run 与 revision／attempt／评估归属一致，`run_id + event_sequence`、幂等键等唯一；所有必需关系显式外键校验。大 JSON 可作为版本化报告快照，但不能用一个无关联约束的 JSON 字段冒充完整数据建模。

迁移脚本、schema 版本、升级测试与备份流程必须交付。开发／自动测试／正式实验使用不同数据库和目录，自动测试不能清空用户数据库；历史结果只能以标注来源的只读导入记录存在，不能变成新系统实测。

## 7. worker、事务与中断恢复

1. API 校验并在短事务中创建 run、入队及首事件，提交后返回；worker 原子认领任务，保存 worker 身份、租约和心跳，首版只允许一个活跃执行者。
2. 模型、浏览器、训练不在长数据库事务内运行；每次外部尝试先记录请求指纹和开始状态，结束后记录响应收据、实际成本及关联 revision，再推进图。
3. worker 崩溃后检查租约、收据、图 checkpoint 与实际文件。存在完成响应时按身份校验复用，不重新生成；调用是否完成不明时进入 review_required，不盲重试付费请求。
4. 文件先写独立临时位置并计算字节哈希，原子提交为新 artifact，再登记可用；数据库与文件不能原子提交的间隙由恢复核对处理。缺失／损坏／孤立文件不得伪造为成功，也不自动删除历史证据。
5. 图状态与业务进度通过持久事件和幂等步骤协调，重放不能重复增加成本、重复接纳候选或覆盖最终产物。cancel 在节点／外部调用安全边界处理，原请求的返回事实仍需登记。
6. 数据库锁定、磁盘满、上传／追踪异常分别登记设施问题，不转成修复 San 的诊断。单 worker 并不免除 HTTP 写入并发，认领和幂等约束必须实测。

这套恢复设计不是跨数据库／LLM 的“恰好一次”承诺。系统必须显式表达无法自动判定的状态，保留审计事实。

## 8. 文件布局与基本安全边界

代码与配置在 `migration_system/`。拟定本地运行目录 `migration_system/var/` 保存业务 DB、图 DB 和临时日志，实施时加入忽略与备份规则；新实验产物使用 `data/experiments/migration_system/<run_id>/`，与旧批次分开。文件目录均由服务配置决定，不由前端自由指定。

- 上传限制文件数、总大小、扩展名和解包层级，拒绝绝对路径、`..` 越界、符号链接等；不因为上传依赖包就自动安装任意包或执行安装脚本。
- 模型凭据只在后端运行环境，前端选择配置 ID，不能传任意模型服务地址来访问内网；日志／数据库／trace 不保存密钥。
- 本机接口检查 Host／Origin 和写请求保护；开发前端使用受控代理或允许列表，不使用任意来源的宽松跨域配置。首版不声称具有公网多用户认证能力。
- 生成脚本在受限独立浏览器进程／上下文中评估，隔离工作台、网络、存储和运行凭据；iframe 不是操作系统级恶意代码沙箱。不默认执行任意外部组件依赖或允许外网访问。
- 下载和预览按 artifact_id 定位，检查根目录边界、哈希及 MIME 类型；不把文件系统路径或运行堆栈中的秘密暴露给网页。
- 终态产物／报告默认不可覆盖，删除不作为首版必需功能，避免误删论文证据。旧冻结目录始终不作为新系统工作目录。

## 9. 开发与验收层次

| 层次 | 真实部分与测试替代 | 验证什么，不验证什么 |
| --- | --- | --- |
| T1 契约／图单元 | 真实数据模型、节点与条件边；模型用假客户端 | 分支、预算、退化回退；不证明真实模型质量 |
| T2 存储／API 集成 | 真实临时文件 SQLite、真实 ORM／迁移、worker 与 Flask 应用；模型假客户端 | 幂等、关系约束、恢复、文件损坏／路径越界；Flask 测试客户端不等于网络联调 |
| T3 前后端联调 | 真正启动前端、HTTP API、worker 和文件 DB，浏览器提交／刷新／下载；模型可暂用显式 stub 模式 | 真实端口和持久化链路可用；stub 标识必须展示和入库，不能进入正式成绩 |
| T4 真实迁移验收 | 真正前后端／DB／worker／LangGraph、授权的模型请求、LangSmith 与 Puppeteer；LoRA 另有真实训练／加载验收 | 整条迁移和修复链工作；必须保留失败／阻断，不要求所有样本成功 |
| T5 冻结研究实验 | 固定实现、数据、参数、预算及评估协议，保留前后结果与所有尝试 | 才能研究迁移率、修复增益和成本，不用 T1—T3 的人工构造结果代替 |

端到端验收至少包括：网页提交到入库／排队／运行／报告／下载；刷新不新建模型调用；失败仍有完整记录；新建任务与旧任务互不覆盖；被拒候选不能出现在最终下载中；人工意见不覆盖自动失败；进程重启后历史和安全恢复有效；同请求重复提交不重复计费；数据库迁移／备份恢复；真实任务可从网页追溯到请求、revision、评估、实际 trace 与成本。

真实模型和外部追踪运行前由用户确认凭据、上传范围和预算。设计稿建立时未运行上述测试；后续 P2b 实测见第 11 节，不能把 P1 的历史定向测试冒称新增全栈验收。

## 10. 下一步落点

P2 分小步交付：先建独立包和配置／契约边界；再建真实数据库模型、迁移、API 与持久 worker；接真实 LangGraph 图和脱敏追踪；用假客户端完成可恢复的持久化纵向链路；随后建立网页工作台并进行 T3 联调。研究阶段 P3—P5 的真实评估和模型能力接入后，P6 必须完成 T4，不把“后台脚本能跑”当作系统交付。

与 P1 契约冲突的字段通过新版本或显式映射处理，不在旧严格 v1 上随意加字段。数据库任务／执行状态是应用层模型，不能擅自改写迁移评估 Status 的含义。

## 11. P2b 开发链路实施记录（2026-11-16）
