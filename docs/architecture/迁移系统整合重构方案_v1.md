## 1. 目标与结论

采用**实验区保留、新系统独立、通用改进经验证后整合**的渐进式重构。现有 SSM、生成、校验、通用修复规则和候选保护作为复用基础；新系统以 LangGraph 为唯一主编排，以 LangSmith 追踪实际决策和模型调用，而非复制整套旧流水线后改名。

先完成最小完整系统，再通过冻结失败输入持续优化闭环；“最小完整”必须包含校验、有限修复、候选复测和失败退出，不能先只做生成页面，把正确性保障留到以后。

本次重构要解决的工程问题：

1. 开发探针与主流水线分散，局部通过不能自动转化为系统能力。
2. 生成 Prompt 与修复 Prompt 的构造位置不同，实际请求及版本需要统一追溯。
3. DOM、原生浏览器、方法投影、人工验证的结论缺少统一但不混淆的结果接口。
4. 规则、诊断、修复分流、候选保护和回归用例需要形成可重复的闭环。
5. 入口、checkpoint、产物版本、成本与失败原因需要统一，避免重复生成或旧结果误用。

工程整合有助于可靠发现和修复错误，但不保证迁移率必然提高，也不承诺消除所有 Vue/San 语义差异。效果由后续统一协议实验验证。

## 2. 范围与明确不做的事项

### 2.1 输入与交付

- 用户输入仍是 Vue 源码及运行该组件所必需的本地依赖、样式和资源；自包含组件不要求额外业务材料。
- 系统内部负责提取 SSM、登记依赖、计算指纹、建立评估页面和保存证据，不要求用户另写 Vue provider 或互操作协议。
- props、代表性交互与预期结果属于评估配置；缺少配置应明确限制覆盖范围，不能假称只靠源码已证明全部行为等价。
- 交付包括网页任务工作台、实际可调用的 API、数据库及变更脚本、可恢复 worker，以及 San 产物、各维度评估、修复历史、终止原因和证据索引；失败也必须有完整报告。首版是本机单用户系统，不等于公开多用户平台。

### 2.2 本轮边界

- 不修改 Vue 源码，不建立源代码勘误版本，不改写冻结输入。用户已明确当前重点不在 Vue 代码上。
- 不增加 Vue/San 运行时互操作、provider、任意外部业务接入协议或整页上线能力。
- 不通过缩小任意公开键契约、抑制源警告、删除诊断或移除失败样本来提高通过率。
- 不把人工修好的 `.san` 当成自动生成结果；不覆盖旧 summary、Notebook、协议、快照及失败证据。
- 必须建设真实任务工作台，但不扩展为复杂多租户管理平台。已有 CLI、HTTP 经验和人工验收页作为复用依据，不能用静态页或几个脚本代替最终前后端。
- r3 方案修订当时只改文档；随后 P2a 的实际新文件及离线验证见第 16 节。旧实验代码不搬移，不在骨架步骤安装运行依赖、运行浏览器／训练／模型或 commit/push。

### 2.3 实验区与重构系统目录

以下是完整目标结构；P2a 已建立其中的独立包、配置／契约边界和预留目录，具体已实现范围以第 16 节及工程 README 为准。代码系统独立，不等于重复复制数据集、快照和历史报告。

实验可继续在旧结构中进行，但实验区不是永久冻结的基线：每次实验都记录实际实现指纹。新系统只能通过显式适配器复用登记过版本／指纹的旧模块；实验模块变动后必须重新确认兼容，不能随意 import 当前工作区而仍宣称新系统未变。

P1 已建立的 `migration_pipeline/contracts/` 暂留原处，作为待整合基础。后续接入新包时采用版本固定的适配或有来源记录的移植，并做往返与黄金样例一致性测试；不能维护两套同名但含义不同的 v1 契约。旧入口继续可用，不能为了新系统而破坏历史复现。

仓库根目录现有 `frontend/` 当前仅为占位，不覆盖它；新工作台在新系统根目录内建立。新产物使用独立 `data/experiments/migration_system/<run_id>/`；数据库、文件产物、图 checkpoint 和 LangSmith trace 各有职责，不将其中任意一项当成全部持久化。

### 2.4 通用改进的整合门槛

每项改进采用以下流程：

1. 冻结输入、代码和评估口径，在实验区复现缺陷或记录机制分析结论。
2. 明确修改属于 SSM、生成 Prompt、校验器、修复 Prompt、规则还是评估设施，并说明适用边界。
3. 提供缺陷正例、边界反例及原本正确情况的保护测试；评估器变更另查误报／漏报，不以“通过数增加”单独判优。
4. 在新系统中进行适配并运行节点／图／集成测试，确认实际请求、诊断、产物版本与回退行为正确。
5. 登记整合清单：来源实现指纹、证据、变更文件、测试、兼容影响及限制。未满足条件只保留在实验区。
6. 冻结新系统版本后再进行整批实验；运行中发现新改进留待下一版本，不把修改混入同一实验批次。

单次生成成功、单组件人工补丁、仅增加 Prompt、关闭诊断或挑最好一次复跑都不能单独满足整合门槛。使用测试集结果调参后应标为开发／探索性证据，不能继续称为未见独立测试。

## 3. 开题要求与当前实现对照

依据：[开题报告](../paper/专业学位硕士研究生选题报告4.docx)研究内容 1.1—1.4、关键问题及研究目标；详细历史审计见 [requirements.json](../../data/experiments/analysis/thesis_closeout_audit_v1_20261115/requirements.json)。下表是当前工程判断，不修改开题要求。

| 开题内容 | 当前可复用基础 | 重构／补证事项 |
| --- | --- | --- |
| 四维 SSM 与 AST 提取 | `SSM/schema/v3.py`、`SSM/extractors/parse_sfc.cjs` | 必须以 `@vue/compiler-sfc`、`@babel/parser` 落实四维提取；定义语法模式分母和标注集，不能用迁移通过率代替 ≥90% 覆盖证据 |
| SSM 驱动生成、few-shot | `stages/generate.py`、`generation_client.py`、服务端生成模板 | 统一请求构造及追踪，核实示例确实进入请求；禁止目标答案泄漏 |
| 结构一致性 | `stages/validate.py`、现有 DOM 比较 | 必须实现目标 San AST 与源 SSM 规范化结构的树编辑距离及节点／属性／事件差异；另报渲染 DOM TED |
| Puppeteer 截图、SSIM、像素、计算样式 | 受控浏览器及像素试点已存在 | 新系统必须以 Puppeteer 执行双端截图和关键样式采集；保留旧 CDP 试点作对照，不作为 Puppeteer 已完成证据 |
| 视觉嵌入辅助指标（关键问题 2.3） | 尚未核实统一实现 | 必须提供冻结模型和预处理的辅助相似度结果，验证其适用性；不能替代像素／SSIM／样式和语义门 |
| 功能及交互一致性 | 方法级检查、原生实例、轻量交互、部分浏览器与人工证据 | 统一登记证据层级，扩展代表场景；局部通过不冒充完整等价 |
| 规则＋模型有限修复 | `stages/repair.py`、scheduler、Prompt、候选回退 | 打通可信诊断 → 分流 → 修复 → 同口径复测 → 接受／回退 |
| LangGraph／LangSmith | 现有 Python 编排与运行记录 | 必须实现真实 StateGraph 节点、条件边和恢复，真实 LangSmith 追踪；普通 Python 循环／本地 JSON 日志不能替代 |
| few-shot／LoRA | 已有生成及配对数据基础，LoRA 完成情况未核实 | 两条路径均落实：few-shot 真实请求与对照；LoRA 数据、训练、适配器加载推理及对照，不把占位脚本算完成 |
| 编译运行 ≥85%、视觉通过 ≥90%、少量人工修改占比 ≥70% | 有历史开发结果与修复链 | 分别定义计数和原始记录；不能用旧综合通过率替代这些目标 |
| 较手工／纯规则的效率、对比及消融 | Token、部分时长和冻结案例 | 补可比实验和原始计时，缺失历史计时不补造 |

本次执行决定以开题路线为准，不再采用“现有 Python／CDP 已有相近功能即可替代”的完成口径。可以复用旧实现中的业务规则、证据保护和指标计算，但新系统必须证明所要求工具和算法确实进入实际主路径。资源不足或效果未达标时如实标记未完成／未达目标，不能自动降为选做。

### 3.1 LangGraph 必须承担真实编排

新系统以实际 `StateGraph` 定义、编译和运行迁移图。节点至少覆盖输入预检、SSM 提取、生成、结构校验、浏览器评估、诊断路由、规则修复、模型修复、候选复测、接受／回退和最终报告。关键决策必须由图上的条件边表达，不能仅用一个节点调用旧的完整 while-loop，再把其余节点画在文档中。

图状态承载统一契约或其显式映射：SSM 引用／指纹、当前接受 revision、候选 revision、差异报告、修复轮数、规则／模型成本及停止原因。持久化 checkpoint 绑定 run／sample、协议、实现、输入及依赖版本；初期采用经版本锁定的本地持久化后端，不用仅内存保存冒充进程重启恢复。节点和边的概念依据 [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)，恢复设计依据 [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)。

验收必须有：真实图执行和可导出的节点／边定义；假客户端覆盖全部路由；进程中断后恢复；版本漂移拒绝；失败候选不覆盖接受版本。LangGraph checkpoint 不单独保证外部 LLM 调用恰好一次：需另存请求／响应收据，对“已发出但响应状态不明”进入复核，不能盲重试并漏记费用。

### 3.2 LangSmith 必须追踪真实决策链

使用 LangSmith SDK 对图运行、阶段节点、规则、模型请求及候选决策进行实际埋点，保存可核验的 trace／run ID，并与本地报告和产物 revision 关联。记录阶段输入输出摘要、路由理由、异常、耗时、实际返回的 input／output／total tokens；缺失 usage 明示未知，不能用字符数估算冒充计费数据。自定义模型调用按官方 [Custom instrumentation](https://docs.langchain.com/langsmith/annotate-code) 和 [Log LLM calls](https://docs.langchain.com/langsmith/log-llm-trace) 接入。

验收分两步：先用假模型验证追踪结构，再经用户确认凭据及数据上传范围，在 LangSmith 中核验一次真实系统执行链及后续授权模型请求。假客户端追踪不算真实模型实验。本地日志是补充和恢复依据，不是 LangSmith 的替代；无有效平台追踪证据时该技术项仍未完成。

上传前定义字段允许列表与脱敏规则，密钥不入 state、checkpoint 或 trace；源码／提示词正文是否上传须明确授权。追踪失败应保留本地事实并标记待补／阻断验收，不为补 trace 重复调用模型，也不把上传失败伪装成组件错误。本轮不连接或上传 LangSmith。

### 3.3 few-shot 与 LoRA 均列入实施

few-shot：从训练／开发材料中选择“SSM → San”示例，冻结选择规则、示例指纹、上下文长度和实际请求；测试答案不得进入示例。零样本与 few-shot 使用可比设置验证，不能只把规则说明称为 few-shot。

LoRA：建立指令＋序列化 SSM＋目标 San 的训练数据；按组件来源／同源变体分组隔离训练、验证、测试，查重并披露已有接触。选择许可允许且可训练的基础代码模型，冻结模型和 tokenizer 版本、低秩配置、目标模块、随机种子、训练参数、环境和预算。可采用 [Hugging Face PEFT LoRA](https://huggingface.co/docs/peft/developer_guides/lora) 实现：需保留可训练参数检查、实际训练日志、适配器权重／配置、加载后推理和未参与调参样本的评估记录；不能以配置文件或一次前向演示替代训练完成。

当前云端 API 名称不代表拥有可微调权重；不预设能在现有 `qwen-plus` API 上直接训练本地 LoRA。基础模型和 LoRA 使用同一基座作配对对照，模型路径不同时单独披露，不能把换模型带来的差异都归因于 LoRA。LoRA 后端接统一生成接口，使用相同校验、评估和修复流程，不要求每次迁移在线训练。

训练所需硬件、模型下载、授权和费用仍需用户确认，但“如何执行／何时执行待落实”不等于“是否实现仍可选”。主流程可先用假模型和既有 API 开发；完整技术路线交付必须补齐 LoRA 训练和推理证据。

### 3.4 结构与视觉必须按开题实现

结构：解析目标 San 模板和脚本形成 AST，建立到四维 SSM 的规范化对应表示；显式处理属性顺序、循环／条件、组件和事件。分别报告源 SSM／目标 AST 的结构 TED 与双端渲染 DOM TED，不对原始异构树生硬比较，也不把字符串／标签序列相似度称为全部 AST 等价。

视觉：在新系统中用 Puppeteer 实际加载两端页面并截图，采集计算样式、DOM、异常和代表性交互；截图调用依据 [Puppeteer Screenshots](https://pptr.dev/guides/screenshots)。在此基础上执行 SSIM、不同像素比例、差异热图和样式差异，补充冻结视觉嵌入模型的辅助指标。旧 CDP 试点的页面隔离、归属校验和保护思路需要重新适配验证，不自动继承可信结论。

UI 还原度（0—100%）的计算公式、分量和阈值应在模型实验前固定；单独保存 SSIM 与实际不同像素比例，不把 `1-SSIM` 改名为不同像素比例。视觉嵌入只作辅助，不能抵消语义／源警告阻断，也不能用主观挑选区域或遮罩隐藏差异。

## 5. 目标主流程与职责边界

```text
Vue＋必要依赖
  → 输入预检／指纹 → SSM 提取 → 生成请求 → 初始 San 产物
  → 静态／编译检查＋运行／结构／视觉／代表性交互评估
  → 诊断归因与分流
      ├─ 证据／设施异常 → 阻断或同版本恢复，不让模型改组件
      ├─ 源基准异常／未支持语义 → 保留阻断，不改 Vue、不降级契约
      ├─ 全部必需检查通过 → 输出通过报告
      └─ 可修复目标缺陷 → 有界规则／模型修复 → 候选完整复测
                           → 接受或回退 → 继续评估／达到停止条件
  → 保存所有尝试、最终产物与统一报告
```

分层职责：

| 层 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 前端工作台／CLI | 提交、展示实际进度、查询报告／差异、下载和人工确认 | 各自复制修复判定、暴露模型密钥、执行生成脚本或覆盖自动分数 |
| HTTP API／应用服务 | 验证输入、建立任务／运行、幂等入队、查询和安全恢复 | 长请求内执行整条图或通过页面刷新触发再次生成 |

| 编排层 | LangGraph StateGraph 控制阶段、预算、checkpoint、候选版本和停止 | 在路由或旧 orchestrator 中另藏一套主循环 |
| 领域阶段 | SSM、生成、校验、评估、修复、候选门 | 自行改变协议阈值或用局部成功签发综合通过 |

### 5.1 真实前后端与持久化交付

工程首版选择 Vue 3＋Vite＋TypeScript、Flask、SQLAlchemy／Alembic、文件型 SQLite、独立单 worker 和本地版本化文件存储。依据是当前本机单用户研究范围和既有 Flask 基础，不宣称 Web／数据库技术由开题报告指定。具体版本在实施前锁定，不在本文凭空写版本号；不为了“完整系统”额外引入多主机、Redis、微服务或用户权限平台。

前端至少包括创建任务、任务列表／详情、阶段与修复记录、代码／截图差异、产物下载和人工验收。后端提供真实 API 与应用服务，API 创建持久任务后返回，独立 worker 执行图；前端轮询进度，刷新不得重新生成。

数据库保存 tasks／runs／attempts／revision／evaluation／diagnostic／decision／人工记录／trace 索引等真实关联，并提供 schema 迁移和备份恢复。数据库执行状态与评估 Status 分开：finished 不等于 pass。LangGraph checkpoint 专供图恢复，LangSmith 专供追踪；二者不替代业务数据库，截图与源码大对象也不强塞入数据库。

详细页面、API、实体、事务／幂等／恢复、文件安全与联调验收见[前后端与数据持久化方案](前后端与数据持久化方案_v1.md)。数据库与图 checkpoint／文件不是跨系统原子事务，要设计关联和核对机制，不宣称天然恰好一次。

## 7. 先统一的数据契约

下列契约在 P1 中已有定义、兼容映射和离线测试，详见[统一数据契约 v1](统一数据契约_v1.md)；尚未接入新系统或旧生产主流程。接入 LangGraph state、checkpoint、LangSmith trace 引用及训练模型版本时，先核对字段需求再做显式映射；若必须扩展严格 v1 字段，另立版本并保留旧读取测试，不能偷偷加入未知字段。

| 契约 | 必需信息 |
| --- | --- |
| `MigrationRequest` | run／sample 标识、源及依赖清单与指纹、SSM 版本、props／场景、协议及预算版本；不含密钥 |
| `ArtifactRevision` | revision、父 revision、来源（generation／rule／model／manual）、代码与依赖指纹、请求和证据引用 |
| `Diagnostic` | 保留原 code，增加来源、阶段、严重度、位置、证据引用、阻断与可修复属性；来源未知不得猜为 target |
| `EvaluationResult` | evaluator／schema／环境版本、输入 revision、各维度结果、原始指标、阈值、覆盖及未执行原因 |
| `RepairDecision` | 处理的诊断、规则适用条件、跳过模型理由或实际模型请求、预算消耗、候选 revision |
| `CandidateDecision` | 前后同口径结果、修复目标是否消除、既有契约有无退化、接受／拒绝及回退指向 |
| `RunReport` | 初始／最终结果、全部尝试、停止原因、各项成本、人工介入、证据索引与冻结指纹 |

结果状态至少区分：`pass`、`fail`、`blocked`、`not_run`、`unsupported`、`execution_error`。未知或未执行不映射为通过；这些是建议新契约值，不能直接改写旧 summary 的含义。

综合通过要求协议列出的全部必需检查均通过且无阻断。如果某项场景未覆盖，只能给出有范围的结论；任意公开键等已保留契约不能以业务场景通过替代。

### 7.1 Prompt 与服务重启

生成和修复不需要共用一个大 Prompt，但需要共用版本登记与请求记录规范：

- 分别保存模板版本、SSM／反馈、few-shot 标识、实际系统／用户消息、非密钥模型参数和响应 usage。
- 通用约束优先复用同一规则定义；避免生成允许的语法被校验器拒绝、修复又生成回来。
- 服务端加载的代码／模板变更按部署方式重启或明确热加载；新批处理进程读取本地模块与常驻服务读取模块是两件事。
- 本文不预设“修改后无需重启”；后续通过请求版本指纹确认实际生效，而不是凭磁盘文件推断。

### 7.2 产物、恢复与重新生成

- 同一次运行中：初始生成一次；后续修复基于当前被接受的 revision。被拒候选保留证据，不能继续冒充当前代码。
- 恢复：源、依赖、协议、实现及请求版本匹配才读取 checkpoint；不匹配时拒绝混用，另建运行。
- 重新生成：是新的 generation 尝试，不自动继承上一轮正确产物；与 repair-only 恢复明确区分。
- 计划新增的“仅评估／从既有产物继续修复”模式必须验证来源与版本绑定，并单列成绩，不能冒充从源码自动生成的完整实验。
- 新默认运行拒绝覆盖已有证据；历史 `--force` 入口保留兼容说明，新协议不允许用它择优替换失败。

## 8. 校验—修复闭环的接受规则

每类通用修复需要完整链条：冻结失败输入 → 源语义／目标缺陷 → 稳定诊断 → 适用边界 → 修复 → 反例及保护测试 → 整组件复测。只加 Prompt 或只检测不形成可靠自动修复，应明确标为“可检测、尚不可自动修复”。

1. 先归因：证据完整性／设施、源基准、目标运行／语义／视觉分别登记。高优先级阻断不能删除低层事实，也不能把源问题送给模型修改 San。
2. 有界规则仅在前提可证明时执行；找不到定义、绑定不明或语义越界时保持诊断，不猜修复。
3. 只有可信、与当前产物绑定的可修复目标问题才能构造模型请求。保留已有静态语义阻断，不因浏览器视觉相同而清除。
4. 候选重新执行所有必需检查，不只验证原报错消失。既有通过契约退化、证据不完整或成本超限时拒绝／停止。
5. 拒绝后回到上一个被接受 revision，记录候选及原因；“回退成功”不等于组件已通过。
6. 按开题设置最多 3 轮自校正修复，初始生成不计入修复轮；每轮最多一次模型修复，规则尝试有独立上限，并分别记录规则步骤、实际模型调用和候选复测。不能通过只限制模型调用、无限执行规则轮次绕过迭代上限。P1 Budget 的模型调用／规则计数是基础字段，修复轮状态还需在图与协议中显式绑定；正式数值在首次请求前冻结。
7. 无进展、重复候选、预算／轮数耗尽、源阻断、未支持契约、执行故障均有明确停止原因，不能无限调用模型直到通过。

### 8.1 浏览器评估接入边界

- 延用已确认的严格口径：像素容差 0、不同像素比例上限 0、SSIM ≥ 0.999999999、关键样式／矩形零差异；源 warning／error 和未知归属阻断。见[确认记录](../../data/experiments/protocols/native_browser_criteria_adopted_20261115/approval.json)。本文不降低阈值，也不把它解释成开题目标阈值本身。
- 固定视口、运行时、主题、字体、时间／随机条件、异步等待与逐页存储；无法稳定或未支持的环境明确阻断。字体二进制等尚未冻结项需在系统验收前补齐，不能把本机零差异外推跨机器保证。
- schema 3／4／5 分别核验其真实证据和能力。新适配器不能把新版改字段冒充旧版，也不能把离线预览许可扩大成自动模型调用。
- 页面／会话登记和存储隔离是系统内部评估保障，不是对用户新增业务协议要求。
- 事件、状态、DOM、样式和异常分别观察；真实输入不以调用组件方法或 `dispatchEvent` 代替。覆盖不到的交互保留 `not_run`／`unsupported`。

### 9.1 最小验收清单

系统工程验收至少覆盖以下场景；它们是能力验收，不是新的迁移成功率样本：

- 正确产物不触发无谓修复；缺失检查／证据不能签发通过。
- 已知目标缺陷进入正确规则或修复反馈，修复后经过同口径复测。
- 源警告、未知会话、浏览器失败、缺失依赖和篡改证据进入相应阻断，不让模型修改组件来掩盖。
- 新候选修掉一处又破坏另一处时能拒绝和回退；原代码、失败候选、请求和报告均保留。
- 模型超时、无进展、重复输出、最大轮数与总预算均能停止，真实调用成本不丢失。
- 中断恢复绑定相同协议及 revision；输入或代码漂移被拒绝，不能混用旧 checkpoint。
- 至少用简单／中等／复杂代表组件走通系统；人工修补产物只作校准／回放，不计作新自动生成通过。
- 真实 LangGraph 图负责主路径和修复路由，持久化恢复经实际中断验证；不是只有依赖声明或一张示意图。
- LangSmith 上能核对节点与模型调用的实际追踪，输入输出按授权脱敏，token 与本地收据一致；假 trace 和本地日志不能替代实际集成。
- few-shot 的真实请求与 LoRA 实际训练／权重／加载推理可复现，基础模型、示例／训练集与测试隔离可审计。
- Puppeteer 实际产生双端截图；AST TED、DOM TED、SSIM、像素比例、样式和嵌入分别有定义及对照，不用一种指标冒充全部要求。
- 浏览器通过真正 HTTP 提交任务，持久入库、排队和 worker 执行后可查看／下载；不是静态前端、内存任务或 Flask 测试客户端单独通过。
- 实际数据库 schema 迁移、关系约束、幂等、进程重启、文件损坏／数据库故障和备份恢复有测试；页面刷新不新建运行，被拒候选不当最终产物下载。
- 真实模型、图、评估和追踪全部联调；人工意见追加到具体 revision，不覆盖自动失败；stub 模式在 UI／DB／报告中明确标注且不能进入正式成绩。

测试分为契约／图单元、真实临时数据库／API 集成、真正 HTTP／网页联调、冻结失败回放、浏览器校准、真实模型端到端及完整开发回归，详见专项方案的 T1—T5。假客户端只替代模型，用于低成本验证可控分支，不能替代真实前后端、DB 或迁移正确率。定向测试数量不当成全仓测试；每次记录实际命令、结果、跳过项和环境。付费调用前先完成假客户端控制分支测试。

## 29. 条件性预算上界与单次计划批准（2026-11-16）
