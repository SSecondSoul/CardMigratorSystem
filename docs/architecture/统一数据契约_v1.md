## 1. 这一步做什么

统一系统内部对“输入是什么、当前是哪版代码、发现什么问题、检查是否执行、修复后是否回退”的表达。用户仍提供 Vue 源码及必要依赖；指纹、内部版本和证据引用由系统后续入口生成，不要求用户另写业务协议。

本步新增 Python 数据模型、严格字典序列化和旧记录只读投影。**尚未替换现有 state、CLI、HTTP、scheduler 或报告写入路径，也未授权任何自动修复。**旧实验结果不重新评分。

实现：

- [v1.py](../../migration_pipeline/contracts/v1.py)：契约模型、枚举、类型及结构一致性校验。
- [legacy.py](../../migration_pipeline/contracts/legacy.py)：旧记录投影，保留原 JSON，缺失信息不补造。
- [tests](../../tests/test_migration_contracts_v1.py)：离线测试、假生成客户端及真实旧记录只读兼容。

## 2. 格式与版本约定

顶层对象使用 `contract_version: 1` 和 `contract_type`（对应类名）。嵌套对象按字段嵌套，不重复增加封套。`to_dict()` 返回可 JSON 序列化的独立副本，`from_dict()`／`load_contract()` 反序列化；这不是浏览器记录 schema 的新版本。

- 构造器要求明确的枚举和类型；反序列化按枚举字符串恢复。不把 `"true"`、`1` 当布尔真，不把布尔值当次数。
- 新契约拒绝未知字段、未知类型／版本、缺失必填字段、非有限数、非字符串字典键和任意 Python 对象。未来变更需显式版本适配，不能静默丢字段。
- `dict[str, Any]` 仅接受 JSON 数据，构造／导出时复制；`frozen` 不等于嵌套字典深度不可变，导出前重新校验。
- SHA-256 使用 64 位小写十六进制；只校验格式，不读文件或认证哈希来源。标识、路径和引用不自动解析，不自动访问网络。
- 缺失成本、版本或来源使用 `None`／明确状态，不能默认填 0、当前版本或“目标错误”。完整的新请求必须有版本绑定；不完整旧记录只进入 `LegacyProjection`。
- 契约不提供密钥字段。旧 raw response、原始 Prompt、`props` 或自由详情可能包含敏感信息，P2 的请求持久化仍需独立脱敏／允许列表；本步不声称已经解决所有日志脱敏。

## 3. 基础状态与来源

| 状态 | 含义 |
| --- | --- |
| `pass` | 该检查声明通过，结论受证据层级、版本、输入及覆盖范围约束 |
| `fail` | 已有明确失败结论；不自动意味着可由模型修复 |
| `blocked` | 存在阻断，不能继续判为通过或擅自修复 |
| `not_run` | 没有执行该检查，含明确跳过；不是失败，也不是通过 |
| `unsupported` | 当前能力／协议不支持，保留未满足项 |
| `execution_error` | 执行过程异常，需另做归因，不能直接当成目标业务错误 |
| `unknown` | 有记录但含义／状态不足，不能猜测通过 |

诊断来源 `origin`：`source`、`target`、`infrastructure`、`evidence`、`unknown`。严重度 `severity`：`error`、`warning`、`info`、`unknown`。两者不互相替代；source warning 可以阻断。

`repairability`：`rule`、`model`、`not_repairable`、`unknown`。只有归因为 target 的诊断才能声明规则／模型路线；声明路线本身不授予模型调用权限。来源未知默认且必须阻断。

证据层级 `evidence_level`：`legacy_declaration`、`static`、`lightweight_dom`、`method_projection`、`native_instance`、`browser`、`manual`。层级不自动升级；方法检查不是浏览器，DOM 分数不是像素分数，人工确认不是自动迁移结果。

## 4. 字段定义

以下“必填”表示构造完整新契约时必须提供；旧记录缺字段不要求用户补齐，而是保留在兼容视图中。

### 4.1 输入、预算与产物

| 对象 | 必填 | 可选／默认 |
| --- | --- | --- |
| `FileFingerprint` | `path`、`sha256` | 无；只描述文件身份，不读取／修改文件 |
| `Budget` | `max_model_repair_calls`、`max_rule_steps` | `max_total_tokens`、`max_elapsed_seconds` 默认未知／未设定；具体预算待新协议冻结 |
| `MigrationRequest` | `run_id`、`sample_id`、`source`、`ssm_schema_version`、`budget`；`protocol_sha256`、`implementation_sha256`、`prompt_set_sha256`、`evaluation_policy_sha256`、`model_config_sha256` | `dependencies`、`scene_configs` 为文件指纹元组；`props` 为 JSON 字典，默认空 |
| `ArtifactRevision` | `revision_id`、`artifact`、`origin` | `parent_revision_id`、`dependency_fingerprints`、`request_ref`、`evidence_refs` |

`ArtifactRevision.origin` 区分 `generation`、`rule`、`model`、`manual`。generation 不继承上一轮候选；rule/model 必须有父版本。完整报告中的版本按父先子后排列，拒绝自引用、重复和不存在的父版本。

请求中某个清单为空只表示声明为空，不证明依赖发现完整。哈希聚合规则、源码／依赖真实读取、SSM 绑定和恢复检查属于后续实现，不在本步凭格式校验完成。

### 4.2 诊断与评估

| 对象 | 必填 | 可选／默认 |
| --- | --- | --- |
| `Diagnostic` | `diagnostic_id`、原始 `code`、`stage` | `message`、`location`、`details`、`evidence_refs`；origin／severity／repairability 默认 unknown，`blocking=True` |
| `EvaluationResult` | `evaluation_id`、`dimension`、`status`、`evidence_level` | `revision_id`、`evaluator_version`、`environment_sha256`、`diagnostics`、`metrics`、`thresholds`、`evidence_refs`、`coverage`、`reason` |

约定：

- 评估指向被检查的 revision。未知时保留 `None`，不能以最终文件名猜历史检查对象。
- `metrics` 是实际指标，`thresholds` 是采用的判定条件，`coverage` 是执行范围。没有像素数据就不生成 SSIM／像素分数。
- `pass` 不能同时包含 blocking 诊断。blocked／not_run／unsupported／execution_error／unknown 必须写明原因。
- 一个最终报告中每个维度一条聚合结果；逐场景证据由 `evidence_refs`／`coverage` 引用。不能只保留成功场景，聚合策略由后续评估协议固定。
- 当前维度名由适配器显式给出，不是用一个总布尔值替代所有检查。原生交互 schema 4／5 仍需专门核验适配，不能仅包进该对象就算接入。

### 4.3 修复、候选与成本

| 对象 | 必填 | 其他字段与限制 |
| --- | --- | --- |
| `RepairDecision` | `decision_id`、`input_revision_id`、`action`、`reason` | `diagnostic_ids`、`rule_ids`、`preconditions`、`model_request_ref`、`candidate_revision_id`、`cost` |
| `CandidateDecision` | `decision_id`、`previous_revision_id`、`candidate_revision_id`、`action`、`reason` | `comparison_policy_sha256`、`before_evaluation_ids`、`after_evaluation_ids`、`rollback_revision_id` |
| `CostRecord` | 无 | generation_calls／model_repair_calls／rule_steps／candidate_rechecks／generation_tokens／repair_tokens／elapsed_seconds／manual_lines／manual_seconds 默认全部 `None` |

`RepairDecision.action` 为 rule／model／block／stop。规则路线须给出诊断、规则 ID 和适用前提；模型路线须给出诊断及实际请求引用。block／stop 不能声称产生新候选。记录可以描述请求超时且没有候选的尝试，不能漏记实际成本。

`CandidateDecision.action` 为 accept／reject／not_evaluated。accept 必须有比较策略和前后评估引用；reject 必须指回上一接受版本。**accept 表示候选被接纳，不等于最终全部检查通过。**比较指标及是否真的无回归仍由 P4 候选门计算。

调用、规则、复测、token、人工行数和耗时分别记录；`None` 不等于 0。不从旧 `repair_rounds` 推断模型调用次数，不从最终 usage 补造所有历史失败成本。

### 4.4 统一报告

`RunReport` 必填：`request`、`status`、`stop_reason`、`required_dimensions`。

其余字段：`revisions`、`final_revision_id`、`initial_results`、`attempt_results`、`final_results`、`repair_decisions`、`candidate_decisions`、`cost`、`evidence_refs`。

- 初始、全部尝试与最终结果分开。失败候选的检查保存在 `attempt_results`，回退后最终版本仍指向上一接受产物。
- 校验产物、评估、修复和候选比较的引用存在且相互绑定；拒绝的候选不能被登记为最终版本。
- pass 至少要求显式非空的必需维度、最终 revision、该 revision 上所有必需检查通过、有评估器版本和证据引用、非旧声明证据；不能用必需维度子集隐藏其他已报非通过结果。
- fail／blocked／unsupported／execution_error 等可在没有产物时返回，不能为凑字段伪造最终代码。
- 这些是结构一致性下限，不会认证证据文件真实性、规则语义、场景完整性或协议阈值。生产放行和修复授权仍须由后续门控实现，不能信任任意调用方构造的 pass 对象。

## 5. 旧字段兼容映射

通过 `project_legacy(payload, legacy_format=..., phase=...)` 显式指定格式，支持：旧 state、单样本 repair report、batch checkpoint 中的一行 sample。整个批次 aggregate 不转换成单样本结论。

| 旧来源 | 新只读视图 | 不做的推断 |
| --- | --- | --- |
| state 的 `initial_validate_result`／`validate_result`／`final_validate_result` | 对应 initial／current／final 的 `static_validation` | 不跨阶段回退；不把 dataclass 扁平默认布尔值当已执行 |
| 同阶段 validate 中 `san_compile_result` | `san_compile` | `skipped=True` 映射 not_run，即使旧 `passed=True`；不补运行成功 |
| 对应 `*_visual_eval_result` | `legacy_dom`，保留 TED／结构／文本指标 | 不升级为 browser_visual，不生成像素／SSIM |
| final 的 `interaction_eval_result` | `legacy_interaction` | 不猜为真实浏览器；跳过不算通过 |
| report 的 `initial/final.validate`、`visual_eval` | 对应阶段的声明视图 | compact 只有计数时标记详情缺失；不自动读 optional state／外部路径补全 |
| sample 的 `initial/final_validation_*`、`initial/final_visual_*` | 对应声明和原 error code | 不用 `status=completed` 推断迁移通过 |
| sample 的 `status=error` | `pipeline_execution=execution_error` | 不根据错误文本猜目标代码有错 |
| `final_passed`、`stop_reason`、sample `status` | `legacy_declared_final_passed`、`legacy_stop_reason`、`legacy_execution_status` | 不作为新的 `RunReport.status` 或生产放行 |
| repair_history／normalization_history／usage／gate／未知字段等 | `to_legacy()` 原样返回独立 JSON 副本 | 不猜版本链、来源、成本口径或重新运行历史尝试 |

所有旧检查的证据层级均为 `legacy_declaration`，没有自动补 revision、评估器版本、依赖图绑定或源／目标归属。旧诊断保留 code 和原详情，来源与可修复性为 unknown；旧 pass 若同时有未归因诊断，视图保守 blocked，但原 pass 原封不动保留。

未执行的 native_runtime／browser_visual／browser_interaction 显式 not_run。布尔值缺失或格式不明为 unknown；完全没有结果为 not_run；相互矛盾字段／畸形列表进入 blocked。新版浏览器记录、未知新契约不自动降级成 legacy。

`LegacyProjection.to_dict()` 不包含原始输入／Prompt／响应，也不包含综合新成绩；`to_legacy()` 才返回完整原始 JSON。后者只用于兼容，不是适合直接输出的安全日志。原始文件不由适配器读取或写入，因此不保留 JSON 空白排版；测试另核对实际输入文件字节未变。

### 使用示例（纯内存，不执行迁移）

```python
from migration_pipeline.contracts import LegacyFormat, project_legacy

old_state = {
    "final_passed": True,
    "final_visual_eval_result": {"visual_eval_passed": True},
}
view = project_legacy(old_state, legacy_format=LegacyFormat.STATE, phase="final")
assert view.to_legacy() == old_state
assert next(x for x in view.evaluations if x.dimension == "browser_visual").status.value == "not_run"
# 原 DOM 声明通过不等于浏览器／综合迁移通过。
```

## 7. 新系统受限请求／报告映射（2026-11-16）

本节接续前述历史记录，未改动 migration_pipeline/contracts 的三个固定源文件或任何 v1 字段。实现位于新工程 reporting/request_snapshot.py、projection.py 和应用服务；仍不是对旧实验的重评分或真实模型迁移结果。

新运行入队即冻结严格 MigrationRequest，存入原 runs.request JSON 的版本化 contract_snapshot。源码路径／哈希、实现绑定、协议／禁用 Prompt／禁用模型／未执行评估策略均来自当时实际值，规范 JSON 哈希后被整个请求指纹绑定。同一幂等键复用原快照。sample_id 为 task:<task_id>，SSM 标明未提取；P1 模型／规则额度为 0，夹具循环预算单独保留。无需用户额外编写协议。

报告接口同时提供：应用事实、fixture_audit、contract_projection 和严格 v1 contract_report。全部记录在一个数据库事务中读取，再做请求／源码／全部产物哈希、attempt 收据、版本父链、检查归属、候选前后检查引用、回退／最终版本和停止理由验证。下载也经过该审计，缺失或冲突不得导出为有效最终产物。

P1 现有来源枚举没有 development_stub，不能为了填满字段将其改标为真实规则／模型修复。夹具版本、检查和比较完整保存在应用账本，不进入 P1 revisions／repair_decisions／candidate_decisions；P1 final_revision_id 为 null。六项未执行质量检查明确 not_run，evidence_level 仅是拟执行类别，无实际指标／评估器版本／证据引用；不把夹具布尔值当质量指标。模型调用／token 为已知 0，人工／总耗时仍 null。

| 应用状态 | P1 RunReport.status | 质量检查 |
| --- | --- | --- |
| queued／running／finished／cancelled | not_run | 六个维度均 not_run，不因夹具控制成功而变 pass |
| review_required | blocked | 同样未执行，不归因为 San 缺陷 |
| execution_error | execution_error | 保留设施运行异常，不制造目标修复诊断 |

快照不存在的旧运行返回 contract_report=null、projection unavailable，且只读查询不回写补齐；快照或引用冲突阻断导出。可读取原冻结绑定的历史记录，但恢复／执行仍需当前绑定一致和有效快照。

本轮新增 29 项投影测试；新工程 104 项＋原 P1 契约 40 项通过，合计 144 个不同定向用例，不是全仓测试或新迁移样本。还需在真实阶段接入时填充实际 ArtifactRevision／EvaluationResult／RepairDecision／CandidateDecision 并保留全部证据，不宣称目前已完成真实迁移报告或全栈验收。

## 8. 真实源 SSM 提取的受限 P1 投影（2026-11-16）

新工程 reporting/extraction_projection.py 只使用已固定的 P1 类型，不修改原契约、来源枚举或字段。提取账本先在同一 DB 快照中读取，并校验源文件、请求、全部登记文件和收据，再构造 EvaluationResult／RunReport；投影本身不执行 Node、生成模型或修改数据库。

新请求使用 registered-ssm-graph-v2，在提取器执行前把 contract_snapshot 存入已有 request JSON：冻结严格 MigrationRequest，以及源阶段协议、禁用 Prompt／模型、零模型／规则预算和显式分类策略描述。run_id 为 ssm:<extraction_id>、sample_id 为 input:<input_id>，不是引用的旧夹具 run 或论文样本 ID；implementation_sha256 是整个冻结集成绑定的规范 JSON 指纹。没有新增表或回填旧请求。

| 实际源阶段事实 | 源 EvaluationResult | RunReport（有预冻结请求时） |
| --- | --- | --- |
| 无完成收据 | not_run，无虚构指标／环境版本 | not_run（执行需复核则 blocked） |
| 已登记、审计通过的 SSM 3.0 输出 | pass／static，revision_id=null | 仍 not_run，无最终 San revision；其他五项均 not_run |
| 已知源语法错误 | fail，origin=source | blocked，不能推断目标迁移失败 |
| 暂不支持的源语法／结构 | unsupported，origin=source | blocked |
| 已知依赖缺失／超时等设施错误 | execution_error，origin=infrastructure | execution_error |
| 已知证据格式／绑定问题 | blocked，origin=evidence | blocked |
| 无法归因的错误码 | unknown，origin=unknown、保持阻断 | blocked |

源阶段 pass 只表示“受限提取器产出了形状与指纹可核对的源 SSM”，不是四维语义正确性／覆盖率、San 编译、结构 TED、浏览器或迁移通过。其 evaluator_version 为 ssm-source-evidence-v1，environment_sha256 绑定实际运行时／解析依赖／解释器指纹，evidence_refs 通过 evidence_index 指向原源码及已登记请求／SSM／收据。覆盖分母未测量，coverage 为空，不补造 ≥90% 成绩。输出 SSM 不放入 ArtifactRevision，也不冒称生成 San。

所有源／设施／证据／未知诊断均不授权目标规则或模型修复。执行需复核时即使存在已核对的源输出，整体仍 blocked，并保留独立 execution-review 评估；不丢弃已知事实。成本仅记录本提取作用域的已知零模型调用／token／修复，未测量耗时和人工成本仍 null，不继承引用的夹具成本。

registered-ssm-graph-v1 历史请求没有预冻结 P1 快照：只读提供 contract_evaluation（当前证据审计视图），contract_report=null，projection=partial_evaluation_only，原因为 historical_request_snapshot_missing_no_backfill。不根据当前策略伪造当时的 MigrationRequest。新 v2 缺快照、未知字段、类型漂移或快照／引用冲突直接阻断，不能静默降级成旧请求。未来策略变更应增加版本并保留旧定义，不原地重解释旧请求。

统一字段在既有 SSM 只读 report API／CLI 返回；原夹具 /runs/{id}/report 的六项 not_run 不被改写。不是完整迁移报告、生产放行或研究结果重评分。详细证据和执行说明见[SSM 提取说明](../../migration_system/SSM_EXTRACTION.md)。
